# ArchCritic 知识库测验系统完善计划

## 一、计划目标

把当前“逐题填写并自行复盘”的学习页面，升级为一个可正式使用、结果可追踪的知识测验系统。

完成后应具备：

- 第一版由用户选择难度，每次从该难度题库随机抽取 5 题。
- 支持单选题、多选题、判断题、识图题和开放式简答题。
- 每道题都有经过审核的答案、解析、知识来源和评分规则。
- 客观题自动判分，简答题按要点给出可解释的匹配结果。
- 有完整的答题、提交、结算、错题复盘和再次练习流程。
- 测验记录与当前账户绑定，刷新页面或重新登录后仍可查看。
- 维持“教学辅助”定位，不把模型生成内容直接当作标准答案。

## 二、现状核查

### 2.1 已有能力

- 前端已有独立知识测试页面，可按知识分类和难度筛选。
- 后端能从 100 张知识卡中抽取 100 道开放式自测题。
- 当前题库覆盖 7 个知识分类：综合 27、场地 26、功能 15、空间 14、结构 8、规范 6、概念 4。
- 当前难度分布为：入门 27、进阶 46、研习 27。
- 题目可以跳转到对应知识卡，保留了学习来源关系。
- 用户填写内容后可以显示“复盘要点”，并自行标记“需要复习”或“已经掌握”。

### 2.2 关键问题

1. **现有内容没有被正确当作答案使用**
   - 100 张知识卡都有自测或设计检查内容，其中 95 张另有“答案要点”章节。
   - 当前解析程序没有读取“答案要点”章节，而是在题目段落中寻找缩进小项；找不到时使用知识卡摘要代替。
   - 因此部分“复盘要点”虽然看起来像答案，实际上来源不稳定，也不能作为正式判分依据。

2. **只有一种开放式题型**
   - 当前接口只有题目、来源卡片和复盘要点，没有题型、选项、正确答案、图片、分值等字段。
   - 前端固定显示文本框，无法呈现单选、多选、判断或识图交互。

3. **没有真正的判分环节**
   - “需要复习 / 已经掌握”完全由用户自己选择。
   - 没有答题提交状态、正确或错误提示、得分、解析、总成绩和通过标准。
   - 开放式回答没有按答案要点核对，也没有说明命中了哪些要点、遗漏了哪些要点。

4. **没有完整的测验流程**
   - 当前虽然能按分类和难度筛选题目，但没有形成一次可保存、可提交的正式测验场次。
   - 没有上一题、答题卡、未答提醒、最终交卷和结算页面。
   - 最后一题的“下一题”直接不可用，没有明确的完成出口。

5. **学习结果不能保存**
   - 回答和掌握状态只存在于当前页面内存中。
   - 返回知识库或刷新页面后记录消失；后端没有测验场次、作答记录、成绩和错题数据。

6. **测试覆盖不足**
   - 现有后端测试只验证知识库详情会隐藏测试章节，没有覆盖题目解析、答案读取、判分或测验接口。
   - 前端基础检查只确认入口存在，没有覆盖完整答题流程。

7. **“返回知识库”按钮样式存在明确冲突**
   - 通用按钮原本带有左右留白，但 `report-top-action-button` 把左右内边距强制改为 0。
   - 测验页按钮没有像知识详情页按钮那样补充专属宽度与内边距，因此宽度只跟随文字，形成截图中的贴边效果。

## 三、产品方案

### 3.1 测验入口与出题范围

第一版进入测试前只提供难度选择：

- 难度：入门、进阶、研习。
- 选择后先确认开始，再从该难度题库随机抽取 5 题。
- 第一版不提供分类、题型、题量和反馈方式等额外设置，减少开始前的操作。
- 每道题作答并提交后，立即显示正确答案、解析和对应知识卡，再进入下一题。

后端仍应生成固定测验场次并保存题目顺序。同一场测验在刷新后保持题目和顺序不变，重新开始才创建新场次。随机抽题、题量设置和更多筛选作为后续扩展，不进入第一版。

### 3.2 题型设计

| 题型 | 主要用途 | 作答方式 | 判分方式 |
| --- | --- | --- | --- |
| 单选题 | 概念辨析、规范基础、案例识别 | 选择一个选项 | 与审核后的唯一答案比对 |
| 多选题 | 多因素判断、设计检查项 | 选择多个选项 | 默认全对得分；后续可增加部分得分 |
| 判断题 | 常见误区与适用边界 | 正确 / 错误 | 与审核后的布尔答案比对 |
| 识图题 | 平面、剖面、流线、构造和案例观察 | 看图后单选、多选或判断 | 第一版采用客观选项判分，避免模型自由识图决定成绩 |
| 简答题 | 设计推理、依据说明和策略表达 | 输入文字 | 按审核后的答案要点给出覆盖情况和参考得分 |

识图题第一版优先采用“图片 + 客观选项”。热点标注、图上连线等复杂交互放到后续版本，避免第一版范围过大。

### 3.3 答案和解析规则

每道正式题必须包含：

- 唯一题目编号和版本。
- 题型、分类、难度和分值。
- 题干；识图题还要有图片、图片说明和授权来源。
- 客观题选项及正确答案，或简答题答案要点与每项分值。
- 答案解析、对应知识卡、来源定位和适用边界。
- 内容审核状态、审核人和审核时间。

未通过审核的题目不能进入正式组卷。题目修改后必须形成新版本，旧测验继续保留当时使用的题目快照，避免历史成绩随内容修改而变化。

### 3.4 判分与反馈

- 单选、判断、第一版识图题：确定性自动判分。
- 多选题：第一版采用完全匹配，防止错选也得高分；在解析中明确正确选项。
- 简答题：按答案要点逐项匹配，展示“已覆盖 / 未覆盖 / 表述不明确”。
- 简答题的自动结果定位为参考反馈；不能仅靠大模型给出不可解释的总分。
- 每道题反馈包括：作答结果、正确答案、答案解析、对应知识卡入口。
- 总成绩包括：总分、正确率、各分类表现、各题型表现、薄弱知识点和错题列表。

建议第一版通过线为 60 分，但应做成配置项，避免写死在页面中。

### 3.5 完整交互流程

1. 选择入门、进阶或研习难度。
2. 用户确认后创建测验，并随机载入该难度下的 5 道题。
3. 顶部显示进度，侧边答题卡显示已答、未答、标记复习状态。
4. 每道题先作答，再点击提交；提交后立即显示答案、解析和本题结果。
5. 查看答案后进入下一题，支持返回已答题复盘，切题不丢答案。
6. 最后一题完成后进入结算页，显示总成绩和分类结果。
7. 错题复盘可查看答案、解析和知识卡，并可只练错题。
8. 历史记录页可查看最近测验，未完成场次可以继续。

## 四、数据与技术改造

### 4.1 题库来源

不要继续在请求时临时猜测 Markdown 的结构。建议在知识库隐藏数据目录中建立独立、可校验的结构化题库，例如 `quiz-bank-v1.json`，Markdown 知识卡继续负责阅读内容。

结构化题库至少包含：

- `question_id`、`version`、`status`
- `question_type`、`category`、`difficulty`、`score`
- `prompt`、`options`、`correct_answer`
- `answer_points`、`explanation`
- `image`、`image_alt`、`image_source_id`
- `knowledge_card_ids`、`source_locators`
- `reviewer`、`reviewed_at`

现有 100 道开放式题可以迁移为草稿：优先读取 95 份“答案要点”；5 份规范检查题需补充明确答案或改造成客观检查题，经人工审核后再进入正式题库。

### 4.2 后端能力

新增账户隔离的数据对象：

- 测验场次：所选难度、题目快照与顺序、状态、开始和完成时间。
- 作答记录：用户答案、是否正确、得分、要点命中和标记状态。
- 测验结果：总分、分类统计、题型统计和错题编号。

建议接口：

- `POST /api/knowledge/quizzes`：按用户选择的难度创建测验。
- `GET /api/knowledge/quizzes/{id}`：恢复测验和已保存答案。
- `PUT /api/knowledge/quizzes/{id}/answers/{question_id}`：保存单题答案。
- `POST /api/knowledge/quizzes/{id}/submit`：交卷并结算。
- `GET /api/knowledge/quizzes/{id}/result`：查看结果与解析。
- `GET /api/knowledge/quizzes/history`：查看历史测验。

现有 `GET /api/knowledge/quiz` 在迁移期保留兼容，正式页面切换完成后再决定是否移除。

### 4.3 前端拆分

避免继续把所有逻辑放在单一页面中，建议拆为：

- 测验设置组件。
- 题目容器和单选、多选、判断、识图、简答五类题目组件。
- 进度与答题卡组件。
- 交卷确认组件。
- 结果统计与错题复盘组件。
- 历史测验列表组件。

状态以服务端测验场次为准，前端只保留正在输入但尚未提交的短暂状态。

### 4.4 样式修正

- 给测验页“返回知识库”使用知识库专属按钮样式，不复用会清空横向内边距的报告按钮规则。
- 按钮建议保持至少 120—140px 宽、左右至少 18px 留白，并与标题区顶部对齐。
- 题目选项、正确/错误反馈、答题卡和结算页沿用现有黑、白、紫主色，不新增与全站冲突的视觉体系。
- 补充窄屏和长题干适配，避免选项、按钮和题图溢出。

## 五、实施顺序

### 第一阶段：修正题库基础

- 定义结构化题目格式和校验规则。
- 将现有 100 道题迁移成草稿，正确读取已有答案要点。
- 完成题目审核状态和来源追踪。
- 补齐最小正式题库：每类知识至少包含客观题和简答题，识图题只使用已授权图片。

完成标准：所有可发布题都有答案、解析、来源和审核记录；错误或未审核题无法进入正式组卷。

### 第二阶段：完成真正的答题与判分闭环

- 新增测验场次、答题记录、自动保存和交卷接口。
- 完成五类题目展示与客观题判分。
- 完成简答题要点反馈。
- 增加上一题、下一题、答题卡、未答提醒和结算页。
- 同期修正“返回知识库”按钮宽度和留白。

完成标准：用户选择难度并确认后可以完成随机抽取的 5 道题，每题提交后立即看到答案和解析，最后得到稳定可复核的成绩。

### 第三阶段：加入学习记录

- 保存未完成测验、历史成绩和错题。
- 增加按错题和薄弱分类再次练习。
- 展示分类和题型掌握情况，不制作没有真实数据支撑的排名或对比。

完成标准：刷新、退出再登录后仍可继续测验，并能查看历史结果和错题。

### 第四阶段：内容扩充与教学验收

- 由建筑学教师审核题干、答案、干扰项、图像和难度标注。
- 核查识图题图片授权与清晰度。
- 用不同年级学生做小规模可用性测试，检查题目歧义、难度和反馈是否易懂。
- 根据审核结果调整题库，不让模型自动改写并直接发布正式题目。

完成标准：内容审核通过，题目难度与分类基本稳定，学生能够独立完成并理解反馈。

## 六、测试与验收清单

### 内容验收

- 每道正式题都有答案、解析、来源、版本和审核记录。
- 所有识图题图片可访问、清晰且有授权记录。
- 相同题号和版本在历史测验中的答案不发生变化。

### 功能验收

- 五种题型均能正常作答、保存、恢复和提交。
- 客观题判分完全确定，重复提交结果一致。
- 简答题能说明命中和遗漏的答案要点。
- 未答提醒、最后一题、交卷、结算、错题复盘均有明确出口。
- 不同账户不能读取彼此的测验和成绩。

### 界面验收

- “返回知识库”按钮文字两侧留白充足，长文字不贴边。
- 长题干、长选项、题图和窄屏下不溢出。
- 正确、错误、未答、已标记等状态不仅依靠颜色区分。
- 键盘可以完成选项选择、切题和提交，图片都有替代文字。

### 自动检查

- 后端覆盖题库校验、按难度出题、题目顺序、五类判分、保存恢复、账户隔离和历史快照。
- 前端覆盖题型渲染、切题不丢答案、未答确认、结算和错题跳转。
- 增加一条从创建测验到查看结果的完整流程检查。

## 七、建议的第一版范围

为了尽快从“自我复盘页”升级到“真实可用的测验系统”，第一版建议控制为：

- 只选择入门、进阶或研习难度，每次随机完成 5 道题。
- 单选、多选、判断、图片客观题、简答五类题型。
- 每题提交后立即显示答案和解析；客观题确定性判分，简答题按人工答案要点反馈。
- 自动保存、交卷结算、错题复盘和最近历史记录。
- 不做固定题量选择、随机抽题、分类或题型筛选、排行榜、考试监考、限时防作弊、复杂图上作答和纯模型主观评分。

这套范围已经能够形成完整测试闭环，同时不会把教学自测扩张成高风险的正式考试平台。

## 八、第一版本地实现记录

- 已接入 94 道具备可用答案要点的题目：入门 26、进阶 41、研习 27。
- 另有 5 道规范检查题缺少答案章节，1 道入门题只有与题目不对应的通用占位答案，暂不发布。
- 已实现单选、多选、判断、识图和简答五类题型，其中识图题使用知识卡已关联的现有案例图片。
- 题目列表接口不返回正确答案；用户提交当前题后，后端才返回判定、答案要点和解析。
- 第一版本地测试期间，当前难度、作答和结果保存在浏览器本地，不新增数据库表，也不影响其他账户数据。
- 账户级历史成绩和跨设备恢复仍保留在后续阶段，需另行进行数据库方案确认。
