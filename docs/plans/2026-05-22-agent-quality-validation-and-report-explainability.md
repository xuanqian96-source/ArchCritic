# ArchCritic Agent 专业性验证与报告可解释性规划

日期：2026-05-22  
适用阶段：方案阶段多 Agent 初步跑通后  
目标：在现有评图流程基础上，进一步提升 Agent 的专业性、准确性、可验证性和报告解释力。

## 一、当前判断

ArchCritic 目前已经初步具备以下能力：

- 输入方案阶段图纸和设计说明。
- 由多个专项 Agent 依次评审。
- 由综合评审 Agent 汇总反馈报告。
- 在前端看到评分、反馈问题和知识库卡片。

后续重点不应只是继续增加 Agent 数量，而应转向三件事：

1. 让 Agent 评得更专业。
2. 让评图结果可以被验证。
3. 让用户看懂“为什么这样评”。

## 二、如何提升 Agent 的专业性和准确性

### 2.1 不应只依赖提示词微调

提示词仍然重要，但如果每次发现问题都只改一句提示词，会很难判断系统到底有没有稳定变好。

后续应逐步形成一套固定的验证材料：

- 有代表性的真实图纸。
- 与图纸对应的设计说明。
- 专家认可的事实标注。
- 专家认可的问题标注。
- 可接受的评分区间。
- 不应误报的问题。

这套材料可以作为 ArchCritic 的评图基准集。

### 2.2 什么是“带标准答案的图纸”

建筑方案通常不存在唯一标准答案，因此这里的“标准答案”不是把方案评图变成选择题，而是为一份图纸准备一份人工认可的参考答案。

一份样本建议包含以下部分。

#### A. 输入材料

- 图纸：
  - 总平面图。
  - 平面图。
  - 分析图。
  - 效果图。
- 设计说明。
- 建筑类型。
- 设计阶段。
- 任务书摘要或基本功能要求。

#### B. 标准事实答案

先验证模型是否看清图纸，再验证它是否会评价。

例如：

```text
是否看见主入口：是
是否看见服务入口：是
是否看见卫生间：是
是否看见楼梯：不确定
是否看见电梯：否
是否存在停车区：是
是否存在主广场：是
是否有明显人车分流：部分成立
```

这类答案适合验证图纸识别能力。

#### C. 标准问题答案

由老师、项目负责人或有评图经验的人写出应识别的问题。

例如：

```text
问题 1：主入口到核心公共空间的进入路径不够明确。
问题 2：后勤服务区与公众活动区关系需要进一步核对。
问题 3：单张平面图不足以判断整体结构可行性。
```

问题标注最好分成三类：

- 必须识别的问题。
- 可以识别的问题。
- 不应误报的问题。

其中“不应误报”非常重要。

例如：

```text
不应误报：不能因为只上传一层平面，就断言整栋建筑缺少垂直交通。
```

#### D. 标准评分参考

建筑评图分数存在合理浮动，不宜要求模型与教师分数完全一致。

更适合使用区间：

```text
功能与流线：70-80 分可接受
场地回应：75-85 分可接受
结构可行性：若缺少结构表达，分数不应高于 65
```

这样更符合建筑设计教学和方案评审的实际情况。

#### E. 标准知识依据

如果后续要验证知识库是否真正参与评图，还可以为样本标注“某类问题应优先关联哪些知识卡片”。

例如：

```text
流线问题应优先关联：
[K3] 公共建筑主要人流组织
[K8] 服务流线独立性
```

### 2.3 评图基准集建议分三步建设

#### 第一步：小型人工基准集

先整理 20 到 30 份图纸样本，不追求数量大，但要认真标注。

建议覆盖：

- 图纸清晰与图纸模糊。
- 图纸完整与图纸不完整。
- 功能组织较好与功能组织存在明显问题。
- 场地表达充分与场地表达不足。
- 结构表达充分与结构表达缺失。
- 多张图输入与单张图输入。

这一阶段的目标是尽快发现系统的明显误判。

#### 第二步：专项验证集

按 Agent 分开准备样本。

功能与流线 Agent 重点验证：

- 是否识别入口。
- 是否识别功能分区。
- 是否识别主要流线关系。
- 是否把不确定内容误写成缺失。

场地 Agent 重点验证：

- 是否识别场地边界、道路、停车、广场和到达关系。
- 是否能区分图纸中可确认的信息与图纸缺失的信息。

结构 Agent 重点验证：

- 在缺少剖面、柱网和跨度数据时，是否会乱下结论。
- 是否能把“结构信息不足”说清楚。

几何形式 Agent 重点验证：

- 是否能说明形体与空间组织的关系。
- 是否避免只做风格化描述。

#### 第三步：课程真实样本集

后续加入真实学生作业，并由老师或课程团队标注。

这类数据最能反映系统在真实教学场景中的价值。

### 2.4 准确性如何验证

准确性不宜只用一个笼统数字表示，应拆开看。

#### A. 图纸事实识别准确率

这部分最适合量化。

例如验证：

- 主入口是否识别正确。
- 卫生间是否识别正确。
- 停车区是否识别正确。
- 主要公共空间是否识别正确。

可关注：

- 准确率。
- 漏识别率。
- 误识别率。

#### B. 问题识别质量

问题判断可关注：

- 应指出的问题识别了多少。
- 不该说的问题误报了多少。
- 是否把“不确定”升级成“必须修改”。

其中最需要压低的是严重误判率。

ArchCritic 少说一条次要建议还可以接受，但如果很确定地说错，会直接损害用户信任。

#### C. 评分一致性

评分更适合验证：

- 是否落在专家给出的可接受区间。
- 与教师评分差距是否合理。
- 明显成熟方案是否普遍高于明显欠完整方案。

#### D. 报告质量人工评审

最终仍应有人看报告。

可以用 1 到 5 分评价：

- 专业性。
- 准确性。
- 可执行性。
- 表达严谨性。
- 是否存在误导。

### 2.5 提升专业性的优先手段

建议按以下顺序推进：

1. 提高输入质量：高清图纸、正确图纸类型、较完整设计说明和任务书摘要。
2. 完善专项知识库：不同 Agent 读取对应领域的知识，不让所有 Agent 只读同一批泛化材料。
3. 加强规则约束：不确定内容不能写成事实，缺图时要降低置信度，问题要说明证据。
4. 用专家标注持续回归验证：每次发现误判，都加入验证集，形成长期积累。

## 三、反馈问题是否应标注知识库依据

### 3.1 判断

应该标注，而且很有必要。

当前报告问题与知识卡片分开显示时，用户很难知道：

- 哪条反馈来自哪类知识。
- 为什么这条问题成立。
- 应该点开哪张知识卡进一步学习。

如果问题和知识依据建立连接，知识库就不只是报告下方的附件，而会成为评图解释的一部分。

### 3.2 推荐表现方式

重点问题和关键建议可以带知识标注。

例如：

```text
主入口到核心公共空间的进入路径还不够明确，建议补充从城市到达、入口前场到门厅的连续关系。[K3][K7]
```

用户点击 `[K3]` 或 `[K7]` 后，可打开对应知识卡片。

### 3.3 不需要每句话都标注

不建议把报告做成每句话都带引用的样子，否则阅读会很重。

建议优先为以下内容标注：

- 必须修改项。
- 重点建议项。
- 关键评分理由。
- 专项问题说明。

对直接图纸事实可以不强制标注。

例如“图纸中可以看到主入口广场”更接近观察事实，不一定需要知识引用。

### 3.4 更严谨的反馈结构

后续一条反馈可以拆成：

```text
问题：
主入口组织不够清楚。

图纸证据：
总图中可见入口广场，但从基地边界到入口的引导关系不清楚。

知识依据：
[K3] 场地回应中的入口到达关系
[K7] 公共建筑入口前场组织
```

这样能把：

- 图纸中看见了什么。
- Agent 为什么判断这是问题。
- 依据了哪些知识。

分开说清楚。

### 3.5 可实现性

这个方向可以实现，而且与当前系统结构匹配。

现有系统已经具备：

- 知识卡片编号。
- 评图时传给模型的知识依据。
- 报告中的知识依据快照。
- 前端知识卡片弹窗。

后续主要要补：

1. Agent 输出“问题与引用编号”的对应关系。
2. 后端保存这层对应关系。
3. 前端把 `[Kx]` 渲染成可点击标注。

## 四、专项评分是否应支持点击展开

### 4.1 判断

有必要，也可以实现。

当前如果只显示：

- 功能与流线：72 分。
- 场地回应：68 分。
- 结构可行性：61 分。

用户仍然不知道：

- 具体弱在哪一项。
- 哪个问题导致扣分。
- 下一轮应优先改什么。

专项分数可展开后，多 Agent 的分工才会真正被用户看见。

### 4.2 对教学价值的意义

专项分数展开有三个价值：

1. 让评分可解释。
2. 让学生知道修改方向。
3. 让不同 Agent 的专业判断不被压缩成一个总分。

### 4.3 推荐交互

更推荐点击专项评分后打开专项报告面板，而不是跳转到新页面。

专项报告面板可包含：

- Agent 名称与头像。
- 专项总分。
- 分项评分条。
- 每个分项的评分理由。
- 专项问题。
- 专项建议。
- 当前优势。
- 不确定观察。
- 对应知识依据。

例如功能与流线 Agent 可以展开为：

```text
功能与流线 Agent

总分：72

分项评分：
- 功能满足：24 / 30
- 功能分区：18 / 25
- 流线分析：16 / 25
- 平面丰富性：14 / 20

主要问题：
1. 后勤流线表达不足。[K4]
2. 主入口与公共空间进入关系仍需强化。[K7]

当前优势：
- 基础功能框架完整。
- 公共空间组织已有层次。

不确定观察：
- 未能确认其他楼层的交通关系。
```

### 4.4 哪些 Agent 适合展开

除综合评审 Agent 外，每个专项 Agent 都适合展开。

功能与流线 Agent 可显示：

- 功能满足。
- 功能分区。
- 流线分析。
- 平面丰富性。

场地 Agent 可显示：

- 场地解读。
- 总图组织。
- 入口与到达。
- 环境回应。

几何形式 Agent 可显示：

- 形体生成。
- 空间构图。
- 几何秩序。
- 形式功能协同。

结构 Agent 可显示：

- 结构体系。
- 跨度与支撑。
- 构造可行性。
- 结构空间协同。

综合评审 Agent 更适合显示：

- 综合结论。
- 跨专项优先级。
- 关键问题排序。
- 下一轮修改路线。

### 4.5 可实现性

这个方向可以实现。

实现时需要保证后端长期保留：

- 每个专项 Agent 的分项评分。
- 每个小分项的理由。
- 每个小分项的证据。
- 专项问题和建议。
- 知识引用编号。

前端再把专项总分做成可点击入口，展示对应专项报告。

## 五、建议推进顺序

### 第一优先级：建立验证集

先知道系统哪里评得准、哪里误判，后续优化才有依据。

### 第二优先级：问题与知识卡片建立引用关系

这会明显提升报告可信度和学习价值。

### 第三优先级：专项评分支持展开

这会提升评分解释力，让多 Agent 的专业分工真正可见。

## 六、最终结论

1. ArchCritic 后续提升质量的核心，应从“持续改提示词”升级为“建立真实图纸评测基准集并持续回归验证”。
2. 报告中的重点反馈应与知识卡片建立引用关系，让用户从问题直接进入依据。
3. 除综合评审外，各专项 Agent 的评分应支持展开，展示分项评分、扣分原因、问题说明、建议和知识依据。

这三项完成后，ArchCritic 会更接近一个可用于教学验证的评图辅助系统，而不只是一个能生成报告的多 Agent 演示流程。
