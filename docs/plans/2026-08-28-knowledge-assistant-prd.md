# ArchCritic 建筑知识助手 PRD

编写日期：2026-08-28
版本：v1.0
状态：第一版功能已实现并完成本地验证
适用范围：知识库总览、知识卡与建筑案例详情页

## 实现状态

第一版已完成：7 个内置工具、默认真实模型调用、自然语言条件提取、案例信息标准化、候选卡片检索、模型返回编号校验、账户级会话保存、当前卡片问答、请求取消、待复核状态提示、AI 推荐结果页及原总览状态恢复。服务器仍使用 `mock` 时接口会明确报错，不生成伪造回答；配置真实默认模型和密钥后即可使用。

## 1. 一句话定位

建筑知识助手不是另一个“打分 Agent”，而是一个面向建筑学习过程的知识导航与学习教练：它理解用户正在做什么、从现有知识库中找到真实存在的案例和知识卡、解释为什么值得看，并帮助用户把学习内容继续用于设计。

## 2. 背景与现状

当前知识库已经具备 100 张知识卡和 50 张建筑案例，前端已有可打开、关闭和拖动的 AI 助手界面，但发送动作仍是交互原型，尚未调用真实模型，也没有“对话结果驱动知识库列表”的后端接口。

现有内容已经具备实现结构化推荐的基础：

- 陈整理的 23 份案例原稿中，18 份顶部包含 `scale` 等结构化信息表字段。
- 最终案例治理数据中的 50 个案例均已有地点、年份、规模和建筑类型字段。
- 案例正文还包含场地、功能、流线、形式、结构、环境策略，以及关联知识卡和相似案例。
- 当前“规模”仍以自由文本为主，可能同时出现建筑面积、展览面积、用地面积、多个来源数字或“待核对”，不能直接作为统一数值比较。

因此，第一版不需要让大模型逐篇阅读所有 Markdown 后自行猜测。后端应先把现有信息表整理为可筛选的案例索引，再由默认 AI 在候选结果中排序和解释。

## 3. 产品目标

### 3.1 用户目标

用户可以：

- 用自然语言描述建筑类型、面积、场地、设计阶段和关注问题。
- 获得与条件相符的案例和知识卡，并知道每一项为什么被推荐。
- 在阅读某张卡片时继续追问，回答必须基于当前卡片或明确引用的关联内容。
- 将一个宽泛的设计问题拆成可学习、可检索、可继续设计的步骤。
- 随时退出 AI 推荐结果，准确回到进入推荐前的知识库标签、分类、搜索内容和滚动位置。

### 3.2 产品目标

- 将“知识—案例—设计—评图—继续学习”连接成连续路径。
- 让推荐结果可追溯到真实存在的卡片编号，不允许模型虚构卡片。
- 对信息不完整、存在冲突或尚未复核的内容明确提示，不把推测写成事实。
- 复用系统默认模型配置，不在助手界面增加模型切换入口。

### 3.3 不做什么

第一版暂不包含：

- 文件上传、语音输入、图片生成和互联网搜索。
- 自动替用户完成建筑方案或给出可直接照搬的唯一答案。
- 评图打分、课程成绩判断或替代教师评价。
- 让模型直接访问全部文件路径、数据库或未筛选的内部治理记录。
- 复杂向量数据库；现有 150 张卡片先用结构化筛选、关键词检索和 AI 排序即可。

## 4. 核心用户场景

### 4.1 按设计任务找学习材料

用户输入：

> 我现在要做一个学校里的博物馆，大约 5000 平方米，位于城市环境，有哪些案例和知识值得先看？

助手应识别：

- 建筑类型：博物馆、校园文化建筑。
- 规模：约 5000 平方米。
- 场地：城市、校园。
- 当前需求：案例与知识推荐。
- 可能需要澄清：是校内博物馆、大学自然博物馆，还是面向城市公众的校园博物馆。

系统先检索候选，再返回案例卡、知识卡、匹配理由和差异说明。部分条件不完全匹配时，应明确写出“面积接近但场地不同”等限制。

### 4.2 阅读过程中的延伸提问

用户在某案例详情中提问：

> 这个案例为什么把入口放在这里？对城市博物馆有什么可迁移的经验？

助手默认只回答当前问题，不改变左侧卡片列表。回答应区分卡片中明确写出的事实、基于图文的专业分析和助手的迁移建议。

### 4.3 从评图问题回到知识学习

用户输入：

> 我的评图反馈说主入口不清楚，人流和后勤流线容易冲突，我应该先学什么？

助手把问题拆成入口识别、公共与后勤分流、功能分区和节点控制，形成一个有顺序的知识卡与案例学习路径。

## 5. 加号工具栏

### 5.1 入口与交互

在助手输入框左侧增加圆形“＋”按钮。点击后，在输入框上方弹出内置工具栏，样式参考用户提供的界面：每一项由线性图标、工具名称和一句灰色说明组成。

交互规则：

- 单击工具后关闭工具栏，并在输入框上方显示一个可取消的工具标签。
- 一次提问只启用一个主工具，避免多个工具规则互相冲突。
- 再次点击已选工具或工具标签的“×”，回到普通问答。
- 用户发送后，当前工具对这一轮提问生效；下一轮默认继续保留，直到用户取消或切换工具。
- 工具栏不使用彩色表情符号；采用统一的 18×18 线性 SVG 图标，与现有界面线条和字体保持一致。当前前端没有图标库，开发时优先使用项目内统一 SVG 组件，不为此单独引入大型依赖。

### 5.2 内置工具

| 工具 | 建议图标 | 说明文案 | 主要输入 | 结果与界面行为 |
| --- | --- | --- | --- | --- |
| 案例推荐 | 建筑轮廓 `Building` | 按类型、面积、场地和关注点找案例 | 建筑类型、规模、地点、场地、设计阶段、关注问题 | 返回案例为主、知识卡为辅的结果集，切换到 AI 推荐界面 |
| 知识查询 | 打开的书 `BookOpen` | 查概念、方法、规范与设计原则 | 概念、问题、阶段、学习难度 | 回答并列出相关知识卡；有结果时显示知识推荐界面 |
| 相似案例 | 叠层卡片 `Layers` | 根据当前案例寻找可比较项目 | 当前案例或用户指定案例、希望比较的维度 | 返回相似案例及相似点、差异点，切换到 AI 推荐界面 |
| 案例对比 | 双栏对照 `Columns` | 对比 2—4 个案例的设计策略 | 案例名称或编号、对比维度 | 在对话中生成场地、功能、流线、形式、结构等对照；列表只显示参与对比的案例 |
| 学习路径 | 路径节点 `Route` | 按目标生成有顺序的学习清单 | 设计任务、当前阶段、已有基础、薄弱问题 | 返回按顺序排列的知识卡与案例混合结果集，切换到学习路径界面 |
| 设计问题拆解 | 分支树 `ListTree` | 把宽泛需求拆成可解决的问题 | 自然语言任务或评图反馈 | 先输出问题树和需要补充的信息；用户确认后再生成推荐结果，不立即改变列表 |
| 当前卡片问答 | 对话问号 `MessageQuestion` | 围绕正在看的卡片继续追问 | 当前卡片、用户问题 | 基于当前卡片和关联内容回答，默认不改变列表 |

第一版建议同时上线以上 7 个工具。界面首屏可以显示 6 项，“当前卡片问答”在进入详情时置顶；在总览页没有当前卡片时不显示。

## 6. 普通问答与工具任务的边界

这是保证界面不混乱的关键规则。

| 用户行为 | 是否改变知识库列表 |
| --- | --- |
| 普通延伸提问 | 否 |
| 当前卡片问答 | 否 |
| 设计问题拆解的第一轮 | 否 |
| 案例推荐、知识查询、相似案例、学习路径 | 是，生成新的 AI 结果集 |
| 案例对比 | 只显示参与对比的卡片，但不覆盖原总览状态 |
| 助手判断用户表达不清 | 否，先追问一个必要问题 |

助手不能仅凭一句含有“案例”或“知识”的普通对话就擅自覆盖列表。只有用户选择工具，或助手在普通对话中明确询问并得到用户确认后，才执行列表切换。

## 7. AI 推荐界面与返回规则

### 7.1 独立结果状态

AI 推荐不伪装成普通搜索，而是独立的结果状态。界面应显示：

- 标题：“AI 为你推荐”。
- 本轮条件摘要，例如“博物馆｜约 5000㎡｜城市/校园｜功能与流线”。
- 结果数量和案例、知识卡数量。
- 每张卡片的简短推荐理由和匹配标签。
- “调整条件”和“返回原总览”两个清晰操作。

### 7.2 返回原总览

进入 AI 推荐前，前端保存一份浏览快照：

```text
主标签 + 二级分类 + 搜索文字 + 搜索结果 + 滚动位置 + 可视卡片锚点
```

返回规则：

- 点击“返回原总览”时，恢复进入推荐前的完整快照，而不是统一回到“全部”顶部。
- 在 AI 推荐中打开卡片详情，再返回时，先回到 AI 推荐结果和原卡片位置。
- 用户再次点击“返回原总览”，才退出 AI 推荐并恢复原先浏览状态。
- AI 推荐界面里的手动搜索只筛选本轮推荐结果；清除搜索只恢复本轮推荐，不退出 AI 推荐。
- 关闭助手面板不会自动清除 AI 推荐结果；结果页顶部仍保留“返回原总览”。

## 8. 案例信息的后端数据设计

### 8.1 数据原则

案例原稿和治理数据可以作为后端索引来源，但必须同时保存“原始值”和“标准值”。标准化结果是检索辅助，不覆盖原文。

建议新增或扩展案例检索记录：

| 字段 | 用途 |
| --- | --- |
| `case_id`、`title` | 唯一定位真实案例卡 |
| `building_types[]` | 支持一个案例属于博物馆、校园文化建筑等多个标签 |
| `building_type_raw` | 保留原信息表文字 |
| `area_min_sqm`、`area_max_sqm` | 统一为平方米的可检索范围 |
| `area_basis` | 标明是建筑面积、用地面积、展览面积或未知口径 |
| `scale_raw` | 保存“约 5700㎡”“两种来源数字”等原始内容 |
| `country`、`city`、`location_raw` | 支持地域过滤并保留原地点表述 |
| `site_contexts[]` | 城市、校园、滨水、历史街区、郊野等场地标签 |
| `year_start`、`year_end`、`year_raw` | 兼容设计、建设、开放时间不同口径 |
| `stages[]`、`dimensions[]`、`tags[]` | 设计阶段、学习维度和主题关键词 |
| `related_knowledge_cards[]`、`similar_cases[]` | 关系加权与学习路径 |
| `review_status`、`human_review_confirmed` | 显示与正式引用边界 |
| `metadata_confidence` | 高、中、低；表示标准化字段可信度 |
| `source_ids[]`、`media_permission_status` | 事实和图片权限追溯 |

### 8.2 面积处理规则

- “约 5000㎡”可标准化为带容差的单值或范围，但保留原文。
- “建筑面积 5000㎡，展览面积 2000㎡”必须拆成两个不同口径，不能只留下一个数字。
- 多个来源不一致时保存范围和冲突说明，置信度降为中或低。
- “待核对”不得参与面积硬筛选，只能作为弱匹配。
- 用户说“大概 5000 平”时采用软匹配，不因 4500㎡或 6000㎡直接排除；推荐理由必须说明差距。

### 8.3 数据整理流程

```text
案例 Markdown / 治理 JSON
        ↓
字段抽取与单位统一
        ↓
冲突、缺失和口径检查
        ↓
人工修正覆盖表
        ↓
生成只读检索索引
```

内容更新后重新生成索引。人工修正单独保存，避免下一次导入时被覆盖。

## 9. 推荐与问答流程

### 9.1 推荐流程

```text
用户选择工具并输入需求
        ↓
助手提取类型、面积、场地、阶段和关注点
        ↓
信息不足时只追问一个最关键问题
        ↓
后端用结构化字段和全文关键词召回候选
        ↓
关联关系与内容审核状态加权
        ↓
默认 AI 只能在候选 ID 中排序、选择和解释
        ↓
后端校验所有返回 ID 确实存在且用户可见
        ↓
返回文字回答、推荐卡片和 AI 结果集
```

第一版召回建议：

- 建筑类型和用户明确的排除条件优先。
- 面积使用接近程度评分，不做僵硬的完全相等过滤。
- 场地、设计阶段和关注主题作为加分项。
- 关联知识卡、相似案例和已确认内容获得额外权重。
- 结果尽量兼顾“高度匹配”和“可形成对照”，避免六张案例只是同一种做法。

### 9.2 基于卡片的问答

当前卡片问答只提供：

- 当前卡片正文。
- 当前卡片已登记的来源与关系。
- 必要时补充少量关联卡片内容。

回答中应提供可点击的卡片编号和标题。没有内容依据时明确说“当前知识库不足以回答”，不能编造书名、页码、规范编号、结构体系或材料结论。

## 10. 接口返回结构

建议新增统一接口：

```text
POST /api/knowledge/assistant/chat
```

请求至少包含：

```json
{
  "conversation_id": "uuid",
  "tool": "case_recommendation",
  "message": "我想做一个约5000平方米的城市校园博物馆",
  "context": {
    "view": "overview",
    "current_card_id": null,
    "main_tab": "all",
    "category": "all",
    "previous_result_set_id": null
  }
}
```

响应必须是结构化数据，而不是只返回一段文字：

```json
{
  "answer": "建议先查看以下案例和知识……",
  "intent": "case_recommendation",
  "clarification_required": false,
  "extracted_conditions": {
    "building_types": ["博物馆", "校园文化建筑"],
    "area_target_sqm": 5000,
    "site_contexts": ["城市", "校园"]
  },
  "recommendations": [
    {
      "id": "PBC-001",
      "kind": "case",
      "reason": "规模接近，并可学习文化建筑与公共场所的关系。",
      "matched_fields": ["建筑类型", "规模"],
      "limitations": ["不是校园场地"],
      "score": 0.86
    }
  ],
  "citations": [
    {"id": "PBC-001", "title": "Gösta Serlachius Museum 格斯塔·塞尔拉休斯博物馆"}
  ],
  "result_set_id": "uuid",
  "ui_action": "show_assistant_results"
}
```

`ui_action` 只允许：

- `none`：仅更新对话，不改变列表。
- `show_assistant_results`：进入新的 AI 推荐结果。
- `update_assistant_results`：在当前 AI 结果中调整条件。
- `focus_current_card`：保持详情，并定位当前卡片。

后端不能直接接受模型给出的任意 ID。模型输出后必须再次检查 ID、类型、可见性和审核状态。

## 11. 模型与会话

### 11.1 默认模型

- 前端不显示模型名称和切换控件。
- 助手统一使用服务器当前配置的默认真实模型。
- 当前开发环境仍可能使用 `mock` 配置；未配置真实密钥时，界面必须提示“AI 助手暂不可用”，不能返回伪造的成功回答。
- 模型调用失败时保留用户输入、已选工具和原页面状态，允许重试。

### 11.2 会话上下文

后端按用户和 `conversation_id` 保存最近对话，并记录每轮使用的工具、当前卡片、结果集和引用 ID。模型只接收完成当前回答所需的最近消息，避免对话过长导致速度下降。

建议第一版保留最近 20 轮；用户关闭面板再打开可继续当前会话。清除会话和建立新对话可作为后续功能，不放入首版工具栏。

## 12. 内容可信度与显示边界

知识库浏览与正式权威检索必须继续区分：

- 可浏览但尚未复核的卡片，可以作为“学习候选”推荐，但界面显示“待专业复核”。
- 涉及事实、规范或明确结论的回答，优先只使用已有可靠来源且完成所需审核的内容。
- 未获得图片公开权限不会阻止文本候选检索，但 AI 不应主动输出或重新传播受限图片。
- 回答必须附真实卡片链接；规范、数据和具体事实还应附来源状态。
- 不向前端或模型暴露本地文件绝对路径、密钥和内部审核人信息。

## 13. 界面状态与反馈

### 13.1 工具状态

- 未选工具：输入框占位为“输入你想询问的建筑问题…”。
- 已选案例推荐：占位为“描述建筑类型、面积、场地和关注问题…”。
- 已选知识查询：占位为“输入想了解的概念、方法或规范问题…”。
- 当前卡片问答：输入框上方显示当前卡片编号与标题。

### 13.2 过程反馈

发送后分阶段显示：

1. “正在理解你的设计条件……”
2. “正在知识库中查找……”
3. “正在整理推荐理由……”

用户应在 500 毫秒内看到第一条反馈；候选检索目标在 1 秒内完成；完整回答目标在 15 秒内返回，30 秒超时后明确提示重试。

### 13.3 空结果

如果没有完全匹配结果：

- 不显示空白列表。
- 说明未满足的条件。
- 提供“放宽面积”“保留类型但放宽场地”等可点击调整项。
- 相近结果必须标注差异，不能伪装成完全匹配。

## 14. 首版范围

### 14.1 首版必须完成

- 输入框“＋”按钮、7 个工具及统一图标。
- 真实默认模型调用和明确的不可用状态。
- 案例信息索引与面积等字段标准化。
- 结构化召回、关键词检索、关系加权和 AI 候选重排。
- 卡片 ID 校验、引用链接和审核状态显示。
- AI 推荐独立结果界面和完整“返回原总览”恢复。
- 当前卡片问答、澄清问题、加载、超时、取消和重试状态。
- 对话和结果集按用户隔离。

### 14.2 后续再做

- 向量检索和用户长期学习画像。
- 收藏、学习进度、推荐原因反馈和个性化排序。
- 上传任务书、图纸或照片并联合检索。
- 语音输入、联网搜索和外部案例扩展。
- 将评图报告问题一键带入助手并生成个人学习任务。

## 15. 验收标准

### 15.1 工具栏

- 点击“＋”后能看到 7 个带图标和说明的工具。
- 选择、取消和切换工具后，界面与请求参数一致。
- 总览页的“当前卡片问答”不可误用；详情页能自动带入当前卡片。

### 15.2 推荐正确性

- 所有推荐 ID 必须在当前知识库真实存在，模型不能新增编号或标题。
- 输入“约 5000㎡、城市校园、博物馆”时，返回结果能体现类型、规模和场地匹配，并说明不完全匹配项。
- 面积口径不同或数据待核对时必须显示限制说明。
- 没有匹配项时提供放宽条件，不返回伪匹配结果。

### 15.3 页面状态

- 普通问答和当前卡片问答不会改变列表。
- 进入 AI 推荐前的标签、分类、搜索和滚动位置能被完整恢复。
- 从推荐结果进入详情再返回，能回到原推荐卡片位置。
- 推荐结果内的手动搜索和清除，不会误退出 AI 推荐。

### 15.4 可信度与失败处理

- 回答中引用的卡片均可点击打开。
- 待复核内容有明确状态，不以权威结论呈现。
- 未配置真实模型、调用超时或服务失败时有明确提示，不使用静态假回答兜底。
- 用户数据、会话和推荐结果不会串到其他账号。

## 16. 关键产品决定

本 PRD 采用以下默认方案：

1. 助手角色是知识导航与学习教练，不承担评分和教师替代职责。
2. 工具栏首版提供 7 个工具，一次提问只启用一个主工具。
3. 普通问答不改列表，只有明确的检索工具才生成 AI 推荐界面。
4. AI 推荐是独立状态，保存并可恢复进入前的完整总览状态。
5. 陈的案例信息表进入后端检索索引，但保留原文、标准值和复核状态三层信息。
6. 第一版不用向量数据库，先采用结构化字段、全文关键词、关系加权和 AI 重排。
7. 前端不提供模型选择，使用后端默认模型；未接通真实模型时明确报错，不伪造回答。
8. 模型只在后端给出的候选中选择，最终卡片 ID 由后端校验。
