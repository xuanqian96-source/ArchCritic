# ArchCritic 长程 Goal 开发任务书

编制日期：2026 年 7 月 19 日  
任务性质：可交给长程 AI 持续执行的工程与内容建设目标  
适用领域：公共建筑设计教学  
依据：`ArchCritic后续系统开发计划书_2026-07-15.md`、现有六样本两轮测试、新版证据校准盲测结果  
Goal 状态：已创建，执行中  
当前修订：v2（2026-07-20，评分准确性优先）
可回退基线：Git 提交 `267287e`，标签 `v0.3.0-research-baseline`

## 一、Goal 正文

在严格禁止教师分与标注答案泄漏、禁止修改真实答案、禁止针对盲测样本硬编码的前提下，完成 ArchCritic 公共建筑评分可信度与教学知识库长程升级：

1. 建立不少于 20 份高、中、低档公共建筑基准样本和冻结的数据划分。
2. 使从未参与调参的独立测试集达到：MAE 不高于 8 分、中位绝对误差不高于 6 分，并同时通过排序、事实识别、误报、稳定性和运行成功率硬门槛。
3. 整理 3 本有明确使用权限的核心资料、60 张可追溯知识卡、20 个公共建筑案例，其中至少 10 个完成深度分析。
4. 完成固定知识问答、案例检索、评图问题到知识与案例推荐的验收。
5. 评分可信度与教学内容两条主线必须同时通过，才能宣布 Goal 完成。

## 1.1 本次目标修订：评分准确性优先

本次修订不降低原有硬指标，也不取消知识、案例和数据要求，只调整执行先后关系：

1. 先完成“任务书规则—图纸证据—经审核知识—专项等级—确定性总分—教师校准”的可追溯评分闭环。
2. 知识库建设优先服务评分：先补齐会实际进入评图的准确知识、适用阶段、适用建筑类型、评价维度和来源边界，再扩充一般教学内容。
3. 评分 Agent 必须真实收到与自身专项相关的知识；系统必须保存本次实际使用的知识快照和知识如何影响判断的记录，不能只在报告页展示知识卡片。
4. 知识只用于解释标准、限制错误结论和支持建筑学判断，不得包含或暗示被测作业的教师分、人工档位、标注问题答案或样本身份。
5. 在现有六份开发样本上允许做链路回归和错误定位，但不得把它们重新称为独立盲测；最终评分通过仍以不少于 20 份样本中的冻结独立测试集为准。
6. 评分硬门槛达到后，继续完成知识卡、案例、问答和检索的全部验收；两条主线均通过后才生成最终完成报告。

本修订覆盖第十三章中旧的执行顺序；其他验收标准、禁止事项和任务边界继续有效。

## 二、为什么要设置这个 Goal

当前新版证据校准实验虽然把两份盲测 MAE 从 12.90 分降到 12.00 分，但高分样本和低分样本都得到 85.4 分，未形成有效区分。说明：

- 只降低平均误差不足以证明评分可信。
- 四份校准样本无法支撑稳定的教师标尺。
- 当前模型仍可能把图面完成度、表达丰富度误当成真实设计质量。
- 知识库现有 11 个案例笔记大多仍为“待分析”，案例元数据、来源和版权字段不完整。
- 现有知识内容以规范和评图规则为主，尚未达到 3 本资料、60 张分级知识卡的教学目标。

因此，长程任务不得继续围绕现有六份样本反复调整几个分数，而应同时补齐数据、证据判断、评分验证、书籍知识和案例内容。

## 三、最终完成定义

只有以下五项全部成立，AI 才能把 Goal 标记为完成：

1. **数据完成**：基准集数量、档位、复核、授权、匿名化和冻结划分达到要求。
2. **评分完成**：全套独立测试硬指标全部通过，不以某一个平均指标代替其他指标。
3. **知识完成**：3 本核心资料和 60 张知识卡完成来源、分级、引用与问答验收。
4. **案例完成**：20 个案例、10 个深度案例完成字段、来源、版权、检索和联动验收。
5. **系统完成**：自动化测试、前后端构建、历史报告兼容、回退能力和本地运行均正常。

如果任一硬指标未通过，结论只能写“本轮未达到 Goal”，不得使用“基本完成”“总体通过”等模糊表述。

## 四、任务范围

### 4.1 评分可信度主线

- 基准样本导入、匿名化、质量检查和数据划分。
- 任务书结构化要求与评分维度对应。
- 图纸事实识别、证据置信度和不确定信息处理。
- 专项档位、成对排序、锚点比较和总分校准。
- 提示词、评分卡、模型参数、知识快照和校准器版本管理。
- 真实模型回归、误差统计、错误分类和科研数据导出。
- 未达标时保留稳定生产版本，不强制上线实验评分架构。

### 4.2 公共建筑书籍与知识主线

- 资料清单、书目元数据、版本、使用权限和优先级盘点。
- 入门、进阶、大师研习三层知识结构。
- 公共建筑的功能、流线、场地、空间、形式、结构、环境和图面表达知识卡。
- 知识卡引用、问答检索、来源核验和无依据拒答。
- 教材观点、规范要求、案例启发和教师经验分开标注。

### 4.3 公共建筑案例主线

- 博物馆与展览、图书馆与文化中心、社区服务、教育、体育与演艺等公共建筑。
- 案例元数据、图片或图纸来源、版权状态、分析维度和适用边界。
- 场地、功能、流线、空间序列、形态、结构、环境等深度分析。
- 案例筛选、自然语言检索、匹配理由和评图问题联动。

### 4.4 本 Goal 不包含

- 住宅、城市设计、景观、室内等其他垂类扩展。
- 自动生成可直接提交的完整学生设计作业。
- 数据不足情况下的大模型微调或 LoRA 训练。
- 完整教务、班级、成绩发布、支付与商业运营系统。
- 正式云部署、云数据库迁移或公开发布，除非用户另行授权。
- 宣称 AI 分数等同教师最终成绩。

## 五、基准数据要求

### 5.1 最低数量和构成

正式验收前至少具备 20 份可运行公共建筑样本，建议达到 24—30 份。

| 项目 | 最低要求 |
| --- | ---: |
| 总样本 | 20 份 |
| 高分档 | 不少于 6 份 |
| 中档 | 不少于 6 份 |
| 低分档 | 不少于 6 份 |
| 有第二评审者复核 | 不少于 10 份 |
| 独立最终测试集 | 不少于 6 份，每档至少 2 份 |
| 任务书或课程类型 | 最终测试至少覆盖 2 份不同任务书；无法满足时必须明确报告 |

本 Goal 固定分档口径为：低分档低于 75 分，中档为 75—89.99 分，高分档为 90 分及以上。分档只在私有答案侧使用，不得写入被测 Agent 的输入。

第二评审者优先为教师；教师暂时不可得时，可以使用一名教师加一名高年级助教或具有设计课评图经验的研究成员，但必须分别保存原始分、理由、身份类型和分歧，不得伪装成“双教师评分”。

### 5.2 每份样本必备字段

- 匿名样本编号，不包含姓名、学号和成绩含义。
- 建筑类型、年级、设计阶段和任务书版本。
- 原始清晰图纸、图纸类型、页数、分辨率和文件哈希。
- 设计说明及其来源。
- 教师原始分、评分理由、评分时间和评分者类型。
- 可接受评分区间和高、中、低档位。
- 图纸事实、必须问题、可选问题和禁止误报项。
- 信息缺口、低清风险和不能判断的内容。
- 授权状态、匿名化记录、标注版本和复核记录。

### 5.3 固定数据划分

数据达到最低数量后，先写入不可随意改变的划分清单：

- 开发/校准集：约 50%，允许分析错误和调试。
- 验证集：约 20%，用于最多三轮工程优化决策。
- 最终测试集：至少 6 份，约 30%，在模型、提示词、评分卡、知识版本和校准算法冻结后只运行一次。

同一学生、同一项目的不同版本、同一图纸的裁切或导出版本必须进入同一数据分区，禁止跨分区造成数据泄漏。

现有 CASE-001 至 CASE-006 已经参与多轮分析，只能作为开发回归集或历史基线，不得再次命名为“独立最终盲测”。

## 六、评分验收标准

### 6.1 正式通过硬指标

以下指标必须在从未参与调参的最终测试集上同时通过：

| 类别 | 指标 | 通过线 |
| --- | --- | ---: |
| 精确误差 | 平均绝对误差 MAE | ≤ 8 分 |
| 精确误差 | 中位绝对误差 | ≤ 6 分 |
| 尾部风险 | 90 分位绝对误差 | ≤ 12 分 |
| 单例风险 | 任一样本绝对误差 | ≤ 15 分 |
| 系统偏差 | 平均有符号误差绝对值 | ≤ 3 分 |
| 教师区间 | 落入可接受区间比例 | ≥ 80% |
| 排序 | Spearman 等级相关 | ≥ 0.70 |
| 档位区分 | 高分—低分成对排序正确率 | ≥ 90% |
| 档位区分 | 相邻档位成对排序正确率 | ≥ 75% |
| 图纸事实 | 事实识别准确率 | ≥ 85% |
| 图纸事实 | 确定性错误率 | ≤ 10% |
| 问题识别 | 必须问题召回率 | ≥ 80% |
| 误报控制 | 禁止误报不触发率 | ≥ 90% |
| 稳定性 | 固定回归样本 3 次总分标准差 | ≤ 3 分 |
| 运行稳定 | 固定样本完整跑通率 | ≥ 95% |
| 时间 | 评图总时长 | 95% 样本 ≤ 285 秒 |

**优秀目标**：在满足全部硬指标的基础上，独立测试 MAE 达到 6 分以内。

### 6.2 防止“平均数好看但系统无效”

出现以下任一情况，即使 MAE 达标也判定失败：

- 高分与低分样本大量得到相同或近似分数。
- 预测分数方差明显塌缩，无法反映教师排序。
- 低分样本被稳定评为优秀档，或高分样本被稳定评为低档。
- 事实识别错误被写成确定问题并影响分数。
- 校准后误差下降，但原始专项判断和理由仍与教师评价相反。
- 通过删除困难样本、忽略失败运行或只报告最好一次得到指标。

### 6.3 研究性指标

以下指标必须记录，但第一阶段不单独作为完成门槛：

- RMSE、Pearson 相关、95% 置信区间。
- 各档位分别的 MAE、偏差和召回率。
- 各 Agent 评分区间命中率。
- 每份样本的分数区间覆盖情况。
- 模型调用成本、平均耗时、失败类型和重试次数。
- 任务书强制要求、弹性要求与选配要求核对准确率。

## 七、知识库验收标准

### 7.1 书籍和知识卡

| 项目 | 通过线 |
| --- | ---: |
| 核心资料 | 3 本或 3 组权威资料 |
| 知识卡总数 | 60 张 |
| 入门层 | ≥ 20 张 |
| 进阶层 | ≥ 20 张 |
| 大师研习层 | ≥ 20 张 |
| 必填来源字段完整率 | 100% |
| 其他字段完整率 | ≥ 95% |
| 固定知识问答 | 30 题，每层至少 10 题 |
| 诱导编造或无依据问题 | ≥ 10 题 |
| 有依据回答有效引用率 | ≥ 90% |
| 引用与结论一致率 | ≥ 90% |
| 无依据时伪造来源 | 0 次 |

每张知识卡至少包含：标题、层级、学习目标、前置知识、适用建筑类型、设计阶段、评价维度、学生版解释、关键术语、关联卡、关联案例、自测题、书名/作者/版本/章节/页码或 URL、来源类型、版权状态、允许使用范围、整理人、复核人和版本号。

### 7.2 内容类型必须分开

- `规范要求`：必须能够定位标准编号、版本和条文位置。
- `教材观点`：标明书名、作者、版本、章节和页码，不冒充法规。
- `案例启发`：说明来源案例、适用条件和不可照搬的边界。
- `教师经验`：标明经验来源和审核状态，不写成普遍强制规则。
- `AI 总结`：必须绑定所依据的原始来源，不作为独立权威来源。

## 八、案例库验收标准

| 项目 | 通过线 |
| --- | ---: |
| 公共建筑案例 | ≥ 20 个 |
| 深度分析案例 | ≥ 10 个 |
| 案例字段完整率 | ≥ 95% |
| 可靠项目来源 | 每案例 ≥ 1 个 |
| 图片/图纸来源和权限 | 每个媒体文件 100% 有记录 |
| 固定自然语言检索任务 | 20 个 |
| 前 5 条结果相关数量 | 每任务 ≥ 4 条 |
| 评图问题联动任务 | ≥ 20 个，覆盖至少 5 类问题 |
| 联动推荐相关率 | ≥ 85% |
| 抽查未核实事实 | 0 条 |

每个案例至少包含：项目名称、建筑师、地点、年份、规模、建筑类型、可靠来源、媒体来源与许可、场地策略、功能组织、流线、空间序列、形态、结构、环境回应、关键图纸、3—5 条可迁移启发、适用边界、关联知识卡、相似案例和审核状态。

深度案例必须同时具有场地、功能/流线、空间/形式、剖面或结构四类中的至少三类可靠证据，只有效果图或二手图片的案例不得计入深度案例。

## 九、允许的数据来源

### 9.1 第一优先级：团队合法持有资料

- 课题组、学院或教师明确授权用于内部教学与检索的书籍、讲义、课程材料和案例资料。
- 学校图书馆依法订阅且许可内部研究使用的数据库内容。
- 团队自行拍摄、绘制或获得作者授权的图纸和照片。
- 学生明确授权且完成匿名化的课程成果。

这类资料可以用于内部检索，但是否可以在公开 Demo 展示，必须单独记录，不得因“团队有文件”就默认可以公开。

### 9.2 规范和标准

- [全国标准信息公共服务平台](https://std.samr.gov.cn/)：核对标准题录、状态和版本。
- [国家标准全文公开系统](https://openstd.samr.gov.cn/)：在系统允许范围内阅读或下载公开的国家标准全文。
- 国家或地方政府、住建主管部门官方网站公开的现行规范与政策文件。

标准网页可以作为权威来源，但仍要记录标准编号、发布日期、实施日期、现行/废止状态和访问日期。

### 9.3 合法书籍与研究资料来源

- [中国国家图书馆](https://www.nlc.cn/web/select.html)：用于书目、版本、馆藏和依法开放数字资源核验。
- [Directory of Open Access Books](https://www.doabooks.org/)：检索经过开放获取标记的学术图书，并逐本核对许可。
- [Getty Research Portal](https://www.getty.edu/research/tools/portal/)：检索可访问的建筑、艺术史和物质文化数字化文本。
- [OpenAlex](https://developers.openalex.org/) 与 [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)：补充论文、图书、章节、DOI、作者和开放获取元数据；元数据不等于全文使用授权。
- 高校机构知识库、出版社官方页面和作者正式开放的论文或章节。

禁止从盗版书站、网盘分享、破解数据库或来源不明 PDF 获取内容。只有“网页可以打开”并不代表允许复制全文进入公开产品。

### 9.4 公共建筑案例来源

- 建筑师事务所、业主、博物馆、学校、公共机构的官方项目页。
- [EU Mies Awards Archive](https://eumiesawards.com/archive/) 等官方建筑奖项项目档案。
- [AIA COTE Top Ten](https://www.aia.org/design-excellence/awards/cote-top-ten-award) 等官方奖项和性能案例页面。
- 建筑师、摄影师或机构发布的明确授权媒体包。
- 经过核验的论文、专著、展览图录和项目技术报告。
- ArchDaily、Dezeen 等媒体可作为二手线索或交叉核对来源，但不得自动认为其图片和图纸可复制使用。

案例的重要事实至少由一个第一方来源支持；关键规模、年份、建筑师等信息冲突时需要第二来源交叉核对。

### 9.5 图片和图纸来源

- 团队自有或明确书面授权材料。
- 第一方项目页中明确允许教育展示或下载的媒体。
- [Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en) 中逐文件核对许可的媒体。
- CC BY、CC BY-SA 或公有领域材料，但必须按具体许可署名、链接许可并标记修改。

Google 图片、Bing 图片和普通网页搜索结果只能用于定位来源，不能作为图片版权来源。

### 9.6 每条内容必须记录的来源字段

- `source_title`
- `source_author_or_organization`
- `source_url_or_file`
- `publication_or_project_date`
- `accessed_at`
- `source_type`
- `license_or_permission`
- `allowed_use`: `internal_only`、`demo_allowed`、`public_allowed`
- `attribution_text`
- `original_file_hash` 或网页快照哈希
- `review_status` 与 `reviewer`

来源或许可缺失的内容只能进入待整理区，不能计入验收数量，也不能进入公开 Demo。

## 十、明确禁止事项

### 10.1 严禁答案泄漏

- 不得把教师分、人工分档、评分区间、标注答案、问题清单或“高分/低分”标签发送给被测评图 Agent。
- 不得在文件名、目录名、项目名、图片水印、任务书摘要或知识卡中隐藏教师分。
- 不得告诉模型“该作业应为 94 分”“这是一份低分作品”等答案信息。
- 不得使用人工标注中的评分理由直接引导同一测试样本的模型评分。
- 校准程序只能读取开发/校准集答案，禁止读取最终测试集教师分进行拟合。

### 10.2 严禁针对样本作弊

- 不得按 CASE 编号、文件哈希、项目名称或图纸特征硬编码分数。
- 不得为某一份已知作品编写专属加分或减分规则。
- 不得看到最终测试结果后继续修改系统，再用同一测试集宣布“盲测通过”。
- 不得反复运行最终测试并只选择误差最小的一次。
- 不得删除困难样本、失败运行、超时记录或不利结果。
- 不得修改教师原始分、人工标注或数据分区来降低误差。

### 10.3 严禁用技术假象换指标

- 不得把所有样本压到教师均值附近，以较低 MAE 掩盖排序失效。
- 不得只改最终显示分数，而不修复事实、档位和理由冲突。
- 不得降低图纸清晰度、少发页面或更换任务书以规避难题。
- 不得把看不清写成“缺失”并确定扣分。
- 不得把选配、参考或任务书未要求内容作为强制扣分项。
- 不得使用施工图深度要求压低低年级方案阶段作品。

### 10.4 严禁不合规内容操作

- 不得下载或使用盗版教材、破解数据库、来源不明的书籍 PDF。
- 不得批量抓取和公开展示版权不明的案例图片或建筑图纸。
- 不得把内部授权材料转为公开下载资源。
- 不得伪造作者、书名、页码、条文号、案例信息或图片许可。
- 不得把 AI 总结反向标记为原始教材或官方规范。

### 10.5 严禁未经授权的系统操作

- 不得删除数据库、学生图纸、历史报告、基准原始文件或失败实验记录。
- 不得修改或输出 API 密钥、账号密码和完整环境变量。
- 不得向外部模型发送私有图纸、书籍全文或学生数据，除非用户对该批数据和目的明确授权。
- 不得自行推送 GitHub、部署云服务器、发布公开 Demo 或进行数据库迁移。
- 不得为了本 Goal 修改登录、账户隔离、历史版本、现有 UI 风格和其他无关功能。
- 不得在验收通过前把 `evidence_v2` 或其他实验评分模式设为产品默认。

## 十一、允许修改的内容

在不破坏兼容性的前提下，AI 可以修改：

- `backend/app/agents/` 中与事实、证据、专项判断和综合评审有关的模块。
- `backend/app/scoring/` 中的全局评分、区间、排序和校准算法。
- `backend/app/benchmarking/` 与 `backend/scripts/benchmark_review.py`。
- `backend/app/services/taskbooks.py` 和结构化任务书规则。
- 知识库的索引、结构化知识卡、案例卡和维护记录。
- 与知识问答、案例检索、评图联动直接相关的后端与前端模块。
- 相应自动化测试、实验配置、README、ARCHITECTURE、CONTEXT 和研究报告。

新增数据结构或接口时必须保持旧报告可读；确需数据库写操作、迁移或文件删除时，必须先获得用户确认。

## 十二、不得改动的稳定基线

- 本地账户登录、密码哈希、会话 Cookie 和账户数据隔离。
- 现有项目、提交、图纸、历史版本和报告的所有权关系。
- 现有前端整体视觉风格、页面主流程和 4173 端口约定。
- 后端 8000 端口、五分钟评图预算和全部图纸输入原则。
- 已冻结的教师原始分、人工标注原件和历史正式实验结果。
- `legacy_v1` 稳定回退能力。
- 私有基准集不进入公开 Git 仓库的规则。
- Git 标签 `v0.2.0` 和 `v0.3.0-research-baseline` 指向的历史设计不得改写或移动；新评分方案必须通过新提交和新标签保存。

确需改变以上内容时，AI 必须停止并说明原因、影响和备选方案，等待用户决定。

## 十三、长程执行流程（v2 评分优先）

### 阶段 0：冻结可回退基线

交付物：当前代码状态、历史指标、模型版本、提示词指纹、知识库清单、失败案例清单、Git 提交和不可移动标签。

验收：能够从本地文件复现现有 6 样本历史结果；明确 `legacy_v1` 为产品默认，`evidence_v2` 为研究模式；当前基线可由 `v0.3.0-research-baseline` 找回。

### 阶段 1：评分链路与误差地图

交付物：从任务书、图纸、知识检索、专项判断、总分到校准的完整数据流；逐样本误差、档位混淆、事实错误、问题漏报/误报和稳定性报告。

验收：每个重要错误绑定样本、Agent、图纸证据、知识依据、模型、提示词和代码版本；明确知识是“实际影响判断”还是“仅展示”，不能只记录总分误差。

### 阶段 2：知识参与评分的工程闭环

依次完成：

1. 按建筑类型、阶段、专项维度和任务书规则检索知识，避免所有 Agent 共用同一组泛化材料。
2. 每个专项只接收适用且已审核的知识，并区分规范要求、教材观点、案例启发、教师经验和 AI 总结。
3. 模型输出必须记录引用了哪条知识、支持了哪个判断、是否只起边界限制作用；不存在的知识编号必须被后端拒绝。
4. 知识不得直接给出最终数值分，案例不得作为“长得不像就扣分”的模板；最终数值由后端固定规则生成。
5. 报告保存本次知识候选、实际使用知识、引用和评分审计快照，历史报告不得随知识库更新改变。

验收：自动化测试证明知识会进入正确 Agent、错维度知识不会进入、虚构引用会被丢弃、没有知识时可安全降级、旧报告仍可读取。

### 阶段 3：开发集评分优化

优先顺序：

1. 修复图纸输入、跨页读取和事实识别。
2. 修复任务书强制/选配/阶段要求理解。
3. 修复专项档位、证据置信度和成对排序。
4. 使用经审核知识减少事实误判和错误扣分。
5. 最后才拟合独立教师评分校准；校准不能纠正与教师方向相反的专项判断。

每次修改必须有假设、目标错误类型、代码版本和回归结果。现有六份样本只作开发回归，不产生新的独立盲测结论。

### 阶段 4：数据治理与冻结划分

交付物：20—30 份样本目录、匿名输入、物理隔离答案、授权记录、质量报告和固定划分清单。

验收：没有成绩文件名和身份泄漏；高、中、低档数量达标；同源样本不跨分区；最终测试答案未被开发代码读取。

### 阶段 5：冻结验证集迭代

- 同一冻结验证集最多进行三轮优化。
- 每轮开始前记录唯一主要假设或一组明确关联的改动。
- 每轮使用相同模型、温度、图纸、任务书、知识快照和指标。
- 如果三轮后仍无可靠改善，停止继续调参，报告瓶颈并等待新增数据或用户决策。

### 阶段 6：评分准入测试

先在冻结验证集达到第六章全部硬门槛，再冻结模型、提示词、评分卡、知识版本、校准器和代码提交。未达到时不得进入最终测试。

### 阶段 7：知识与案例完整验收

补齐 3 组核心资料、60 张知识卡、20 个案例和人工复核，运行 30 个知识问题、20 个案例检索任务和 20 个问题联动任务。逐条保存输入、返回结果、引用、人工判定和失败原因。

未通过时只能修复内容或检索后重新运行知识专项；不得借知识内容向评分样本泄露教师答案。

### 阶段 8：最终一次性测试

测试前冻结：

- 模型及供应商。
- 提示词和输出 Schema。
- 评分卡和任务书规则。
- 知识库与案例库版本。
- 校准算法与参数拟合方法。
- 代码提交或完整补丁指纹。

冻结后才允许解封最终测试集。最终测试只运行一次正式统计。若模型服务失败，可对明确的技术失败重试，但必须保留失败记录；不得因分数不理想重试。

### 阶段 9：产品准入、版本发布与总结

只有全部硬指标通过，才可以提出把实验评分模式切换为产品默认。切换前仍需：

- 后端完整测试通过。
- 前端类型检查与构建通过。
- 前后端服务检查通过。
- 旧报告和历史版本兼容检查通过。
- 回退开关有效。
- 工作报告、科研数据和已知限制完整。
- 建立新的版本提交和标签，并验证从 `v0.3.0-research-baseline` 与新标签均可恢复对应设计。
- 只有评分与知识两条主线全部通过后才生成“Goal 完成报告”；此前只保留内部阶段记录，不向用户宣称完成。

## 十四、模型调用与成本边界

- 先运行本地单元测试和模拟链路，再调用付费模型。
- 每个冻结数据划分最多三轮开发/验证实验。
- 每轮只运行计划中需要的样本，不重复已经成功且输入未变的样本。
- 所有调用记录供应商、模型、温度、提示词指纹、输入哈希、耗时、token 或费用、重试和错误。
- 不使用并发导致服务不稳定时，改为顺序运行，不改变实验条件。
- 真实私有资料发送至外部模型前，必须确认用户授权范围。
- 没有用户给出的金额上限时，不得自行进行大规模自动调参、全模型网格搜索或高成本批量实验。

## 十五、必须生成的交付物

### 15.1 评分与数据

- 基准集数据字典和固定划分清单。
- 匿名输入与物理隔离的标准答案。
- 模型、提示词、评分卡、知识库和校准器版本记录。
- 开发、验证、最终测试的原始 JSON。
- 逐样本、逐 Agent、逐档位 CSV。
- 指标 JSON、误差图、排序图和稳定性图。
- 失败样本与错误分类报告。
- 最终产品准入或不准入结论。

### 15.2 书籍与知识

- 书目、版本、来源、权限和优先级清单。
- 3 本核心资料档案和 60 张知识卡。
- 30 个固定问答及人工验收记录。
- 内容审核、版本和待修订记录。

### 15.3 案例

- 20 个案例卡和至少 10 个深度分析。
- 每个媒体文件的来源、作者、许可和署名信息。
- 20 个固定检索任务和结果判定。
- 20 个评图问题联动任务和结果判定。

### 15.4 工程与汇报

- 更新后的代码、自动化测试、README、ARCHITECTURE 和 CONTEXT。
- 面向非技术人员的工作总结。
- 面向论文的实验方法、结果、限制和复现说明。
- 所有未通过指标和未解决风险，不得只写成功内容。

## 十六、暂停与请求用户决策的条件

遇到以下情况，AI 应暂停相关分支并请求用户决定，而不是擅自扩大范围：

- 样本不足 20 份或中档不足 6 份。
- 教师分、任务书、图纸授权或匿名化状态无法确认。
- 需要把私有图纸或受版权保护材料发送给新的外部服务。
- 需要删除文件、写入/迁移数据库、推送 GitHub 或部署云服务。
- 需要购买资料、增加付费 API 预算或安装重型服务。
- 需要改变稳定登录、历史报告、数据隔离或前端主流程。
- 三轮验证优化后仍达不到指标。
- 最终测试失败，需要新的独立测试集才能继续研究。

## 十七、长程 AI 每阶段汇报格式

每个阶段只用以下结构汇报：

1. 本阶段目标。
2. 实际完成内容。
3. 使用的数据与版本。
4. 验收结果：通过项/失败项。
5. 失败原因与证据。
6. 是否触碰任务边界。
7. 下一阶段已授权动作。
8. 需要用户决定的问题。

不得只给总体描述，所有指标必须链接到原始数据或本地文件。
