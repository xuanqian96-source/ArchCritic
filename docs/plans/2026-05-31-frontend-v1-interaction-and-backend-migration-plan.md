# ArchCritic 前端 V1 交互完善与后端迁移计划书

编写日期：2026-05-31  
适用目录：`frontend-v1-replica/`  
目标：在保持 Figma 页面视觉效果不变的前提下，把现有静态 React 页面逐步接入已有后端，形成可实际使用和部署的完整前端。

实施状态：已于 2026-05-31 按阶段完成。新版前端已接通草稿、阶段与 Agent、图纸、任务书、评图、暂停、动态报告、详情、知识追溯、历史版本、项目继承、报告导出和追问；原有 `frontend/` 未修改。验收结果：前端检查 18/18、后端测试 23/23、浏览器完整交互 18/18 均通过。

## 1. 核心结论

当前项目不需要重写后端，也不需要把旧前端整体搬进新版页面。

正确做法是：

```text
保留现有 FastAPI 后端
-> 保留旧版 frontend/index.html 作为功能参考
-> 在 frontend-v1-replica/ 内重新组织 React 状态和接口调用
-> 按新版 Figma 页面逐步接回已有能力
-> 对新版新增功能补充少量后端接口
-> 验收通过后，再把新版 React 前端设为正式入口
```

已有后端已经具备主流程所需的大部分能力：

- 保存项目。
- 保存一次评图提交。
- 上传图纸图片。
- 读取图纸列表。
- 调用演示模型、千问、Gemini 或 OpenAI。
- 通过流式接口实时返回 Agent 评图进度。
- 保存和读取评图报告。
- 返回知识库依据和历史快照。
- 返回历史版本列表。

目前缺少的主要是新版页面新增的交互能力：

- 保存草稿和编辑项目。
- 上传任务书。
- 修改图纸类型、图纸说明、删除图纸和批量删除。
- 保存用户选择的 Agent。
- 暂停评图。
- 报告下载。
- 报告右侧真实追问对话。
- 历史版本各维度趋势。
- 登录和学校账号登录。

## 2. 当前三部分代码分别承担什么职责

## 3. 推荐的完整业务流程

```text
官网首页
-> 登录
-> 项目首页
-> 点击“新建评图”
-> 选择“新建项目”或“继承已有项目”
-> 填写项目基础信息并保存草稿
-> 选择阶段和需要启用的 Agent
-> 上传并整理图纸
-> 确认提交内容和模型
-> 创建正式提交并开始流式评图
-> 在等待页实时显示 Agent 进度
-> 查看报告、知识依据、专项评分详情
-> 继续追问或下载报告
-> 在历史版本页比较历次提交
```

其中，“保存草稿”和“确认提交”需要区分：

- 保存草稿：保存用户当前填写内容，允许继续修改，不调用模型。
- 确认提交：冻结本次评图材料，调用模型，并形成一个历史版本。

## 4. 现有后端接口清单

以下接口已经存在，可以直接接入新版 React 前端。

| 接口 | 当前能力 | 新版前端对应位置 |
| --- | --- | --- |
| `GET /health` | 检查后端是否启动 | 确认提交前、页面恢复时 |
| `POST /api/projects` | 创建项目 | 项目基础信息页 |
| `GET /api/projects` | 获取项目列表 | 项目首页、继承已有项目 |
| `GET /api/projects/{project_id}` | 获取项目详情 | 项目恢复、报告项目信息 |
| `GET /api/projects/{project_id}/submissions` | 获取项目提交记录 | 项目详情、历史恢复 |
| `GET /api/projects/{project_id}/history` | 获取历史版本和总分 | 历史版本页 |
| `POST /api/submissions` | 创建一次提交 | 保存草稿或确认提交 |
| `GET /api/submissions/{submission_id}` | 获取提交详情 | 刷新恢复、历史切换 |
| `POST /api/submissions/{submission_id}/files` | 上传图纸图片 | 上传设计图纸页 |
| `GET /api/submissions/{submission_id}/files` | 获取图纸列表 | 上传页、确认页、历史恢复 |
| `GET /api/submissions/{submission_id}/evaluate-stream` | 流式评图，返回 Agent 进度和最终报告 | 等待评图页 |
| `POST /api/submissions/{submission_id}/evaluate-demo` | 非流式生成报告 | 流式失败时的备用方案 |
| `GET /api/submissions/{submission_id}/report` | 读取已生成报告 | 报告页、历史版本切换 |
| `GET /api/submissions/{submission_id}/references` | 读取知识库依据或历史快照 | 报告页知识库追溯 |
| `/uploads/...` | 访问已上传图片 | 上传页预览、确认页缩略图 |
| `/wiki-assets/...` | 访问知识库图片 | 知识卡片弹窗 |

现有后端图纸上传暂时只接受图片：

```text
PNG、JPG、WEBP、GIF
```

现有后端图纸类型暂时只有：

```text
site、plan、analysis、render
```

新版界面中出现的 PDF、任务书、图纸说明和更细图纸类型，需要后续补充接口。

## 6. 草稿提交策略

新版页面与旧版工作台最大的区别是：用户会在多个页面之间逐步填写内容和上传图纸。

而现有后端图纸上传必须依赖 `submission_id`。因此，推荐把提交分成以下状态：

| 状态 | 说明 |
| --- | --- |
| `draft` | 用户仍在填写信息、选择 Agent、上传图纸 |
| `evaluating` | 已确认提交，正在调用模型 |
| `completed` | 已生成报告 |
| `failed` | 评图失败，可重新运行 |
| `cancelled` | 用户主动取消 |

建议给 `submissions` 增加：

```text
status
enabled_agents
selected_model_provider
selected_model_name
updated_at
```

推荐创建时机：

```text
项目基础信息页点击“下一步”
-> 创建项目
-> 创建 draft 提交
-> 后续页面持续修改同一个 draft
-> 确认提交后把 draft 改成 evaluating
-> 报告完成后改成 completed
```
