# ArchCritic 0829 最终冲刺差距与计划书

编制日期：2026 年 8 月 29 日
适用阶段：8 月 31 日内部冻结前、9 月 5 日参赛提交前
本轮边界：只盘点现状并形成计划，不修改项目代码、知识卡正文或生产数据

## 一、结论

ArchCritic 已经不是一个只有界面的原型。当前已经具备注册登录、任务书和多图上传、多 Agent 评图、知识引用、历史版本、100 张知识卡、50 张案例卡、知识库浏览和建筑知识助手等主体能力。

现在距离计划中的最终成品，主要还差三层：

1. **教学闭环未完全接通**：知识内容可以浏览，但诊断、学习进度、测试闯关、解锁、评图问题回到知识与案例、修改任务和再次提交还没有形成一条连续流程。
2. **内容数量已达标，正式可用状态未达标**：150 张卡片均未完成人工确认；大量图片仅限内部使用或尚未完成公开许可；原始书籍和权威来源档案还不完整。
3. **对外产品准入未完成**：评分仍不能宣称接近教师精度，真实用户试用不足，生产 HTTPS、正式模型、数据备份、完整登录后验收和参赛材料尚未闭环。

最后几天不应继续追求“大而全”。建议冻结为一条连续的博物馆演示路径：

```text
阅读入门知识
→ 查看关联博物馆案例
→ 完成一次小测试并解锁下一步
→ 上传一份博物馆方案
→ 获得带图纸证据的 AI 评图
→ 从具体问题跳回知识卡和案例
→ 形成修改任务并再次提交
→ 查看两个版本的变化
```

这条路径跑通后，图书馆和美术馆继续作为内容覆盖证明，不要求在冻结前分别制作三套完整闯关流程。

## 三、与最终成品相比仍缺少什么

### 3.1 分级学习、测试闯关和学习进度

当前 100 张知识卡已经包含自测题或观察任务，但系统中未发现完整的学习进度、测试记录和层级解锁功能。旧知识库治理资料中已有固定问答、案例检索和问题联动任务草稿，但尚未迁移成当前最终知识库的学生学习流程。

最终成品至少需要：

- 一个入门学习单元，包含学习目标、核心卡片、关联案例和 8—10 道题。
- 记录“已阅读、已作答、得分、最近一次结果、是否解锁”。
- 错题能返回对应知识卡和案例，而不是只显示正确答案。
- 达到约定分数后解锁进阶内容；第一版不做积分、排行榜或商城。
- 评图报告中的具体问题可以一键带入学习路径或助手，形成下一轮修改任务。

8 月 31 日前只需跑通一个博物馆单元，不要求一次完成三层全部课程。

### 3.2 知识库内容、来源、版权和人工审核

当前内容的主要问题不是数量，而是准入状态：

- 100 张知识卡和 50 张案例卡全部为 `pending`。
- 150 条记录的 `human_review_confirmed` 全部为 `false`。
- 498 条媒体记录中，37 条可公开使用，372 条仅限内部使用，89 条尚未获得公开许可。
- 111 条来源记录中，72 条已核验，39 条仍待处理。
- 本地原始资料目录目前有 8 份 PDF，其中 2 本书、1 份案例研究和 5 份设计规范；与治理记录中的三组核心资料并不完全对应。
- 两份本地书籍文件名带有第三方电子书站来源痕迹，不应直接作为公开 Demo 可下载材料或公开展示依据。

最终成品需要把“有卡片”升级为“卡片、原文、引用位置、权利状态和人工责任人能够互相核对”：

1. 为三组核心资料建立正式档案：书名、作者、版本、出版信息、官方或开放获取地址、本地文件哈希、允许使用范围。
2. 原文只用于内部整理，不在公开站点提供整本下载；公开页面只显示必要短摘录和精确来源。
3. 每张知识卡补齐章节、页码或 URL 定位，区分规范要求、教材观点、案例启发、教师经验和 AI 总结。
4. 每个案例核对建筑师、地点、时间、面积口径、关键图纸、图片来源和可迁移边界。
5. 由真实建筑学审核人逐条确认。AI 整理完成不能代替人工批准。

冻结前不建议审核全部 150 张。应先建立一个**公开演示白名单**：约 10—15 张知识卡、5—7 个博物馆案例，要求内容、来源、关系和媒体全部可公开或有明确授权；其他内容继续显示“待专业复核”或仅限内部环境。

### 3.3 案例、知识与评图之间的关联

当前案例与知识卡已有双向字段和 Wiki 链接，结构检查已经通过。但“有关联”还不等于“关联有教学意义”。仍需补齐：

- 关系类型：支持、前置、进阶、对照、相似案例、反例、适用边界。
- 关联理由：为什么这张卡和这个案例有关，而不是只存一个编号。
- 关系强度和来源：人工确认、文本明确支持、AI 建议待核对。
- 评图问题到知识卡、案例、图纸证据和下一版改善状态的完整链路。
- 对用户可见的“为什么推荐”和“能学什么、不能照搬什么”。

最重要的验收不是链接数量，而是选取 3 类典型问题，确认每类都能稳定返回合理知识和案例：

1. 主入口与到达关系不清。
2. 观众流线与后勤流线冲突。
3. 展厅采光、空间高度或展陈条件不匹配。

### 3.4 知识图谱关系图

当前 Obsidian 已能根据双向链接生成基础图谱，也有一份文字版“关系学习地图”；系统网页中尚未形成可交互的关系图。

第一版建议使用现有 Markdown 和治理 JSON 生成轻量关系图，不引入 Neo4j：

- 节点：知识卡、案例、学习层级、评价维度和典型问题。
- 连线：前置、关联案例、相似、对照、支持某类问题。
- 交互：按建筑类型、层级和评价维度筛选；点击节点打开卡片；从当前节点查看一到两跳关系。
- 显示边界：待复核内容、仅内部内容和公开可用内容使用不同状态，不把颜色仅用于装饰。

该功能对演示有价值，但优先级低于测试闭环、内容白名单和正式部署。若 8 月 31 日前时间不足，可先把 Obsidian 关系图和关系学习地图作为后台内容治理证据，网页关系图放在提交后继续完善。

### 3.5 建筑知识助手

助手第一版已经实现，不应再把它描述为“尚未接入”。当前真正缺少的是：

- 使用正式服务器默认模型和密钥完成真实调用。
- 使用正式账号完成登录后的浏览器端到端验收。
- 对 30 个固定问题进行引用正确性、无依据拒答和连续追问验收。
- 把评图报告的问题一键带入助手，生成对应知识、案例和修改学习任务。
- 收藏、学习进度、用户反馈和长期学习画像。
- 后续再评估向量检索；当前 150 张卡片可继续使用结构化召回、关键词、关系加权和模型重排。

冻结前的重点应是“真实可用和不编造”，不是增加更多工具。

### 3.6 评图准确性与可信度

当前证据支持“系统能够辅助发现和组织问题”，不支持“分数已经接近教师”。现有结论包括：

- 九样本实验中，多 Agent 改善了问题覆盖，但没有改善教师分数拟合。
- 视觉锚点测试没有稳定拉开高中低档，当前不作为产品默认。
- `evidence_v2` 仍是研究模式，产品默认继续使用稳定的 `legacy_v1`。
- 现有样本量小、同源性较高，且缺少新增独立教师复核。

最后几天不应继续在旧样本上反复调分。参赛版应把目标改为：

1. 保证看图事实、问题发现、知识依据和修改建议清楚可追溯。
2. 分数继续作为辅助提示，并在页面与材料中明确“不能代替教师成绩”。
3. 用 3 个典型问题形成准确性论证，展示正确发现、误报控制和信息不足时的降级。
4. 冻结当前模型、提示词、评分卡和知识版本，不因个别演示分数不好而重跑挑结果。
5. 新增教师评分样本后，再做一次真正独立的高、中、低盲测；未通过前不切换评分架构。

### 3.7 正式域名部署与生产运行

当前只完成备案期 HTTP 入口，正式 HTTPS 尚未完成。对外成品至少还需要：

- `app.archcritic.cn` 前端 HTTPS 可访问。
- `api.archcritic.cn/health` HTTPS 返回正确的 ArchCritic 健康状态。
- EdgeOne 正式前端指向 HTTPS API，并验证最新构建和 SPA 路由。
- 后端使用真实模型配置，密钥只保存在服务器私密环境变量中。
- CORS、HTTPS Cookie、上传大小、超时和错误提示按生产环境验证。
- SQLite、上传文件、知识库和服务器配置有可恢复备份。
- 固定演示账号、演示数据和离线录屏可用；不能把本地真实账户数据直接当作生产账户数据。
- 至少完成一次“注册/登录—知识库—助手—上传—评图—报告—历史”的公网全流程验收。

生产化还缺数据库迁移、对象存储、监控和限流等长期能力。参赛版可继续使用单机方案，但必须有备份、容量边界和恢复说明。

### 3.8 真实用户、教师审核与交付材料

当前仓库中未找到已经成套完成的正式试用记录、效果验证报告和 3 分钟真实交互视频。最终还需要：

- 至少 2 名真实目标用户的结构化试用记录；原计划目标是 2 名教师和 5 名学生，可按实际可组织人数如实报告。
- 至少 3 个典型问题的输出、人工判断和准确性说明。
- 一个完整的“初稿—AI 反馈—修改稿—版本变化”案例；没有真实修改数据时不得虚构。
- 3 分钟以内的真实系统交互视频。
- 作品方案 PPT、技术报告、效果验证报告、代码说明、模型与服务说明、复现说明。
- AI 生成内容标识、隐私说明、学生图纸授权和内容版权边界。
- 在线 Demo 之外的离线视频、截图和可恢复备份。

### 3.9 其他容易遗漏的内容

除已提出的方向外，还应纳入以下缺口：

- **教师审核入口**：至少用简化表格记录“认可、需修正、不适用”，不必建设完整教师后台。
- **扫描任务书 OCR**：当前只支持带文字层 PDF、DOCX 和 TXT；不是本次冻结阻断项，但要写入已知限制。
- **生产安全与成本**：上传文件类型和大小、模型调用频率、超时、错误日志、密钥保护和费用上限。
- **可访问性与异常状态**：无知识结果、模型失败、图片缺失、网络断开和历史报告兼容。
- **版本与回退**：冻结提交、版本标签、部署版本、知识库版本和回退步骤必须对应。

## 六、需要一起确认的五个决定

建议采用下列默认决定，后续讨论时只需确认是否调整：

1. **演示范围**：以博物馆为连续主线，图书馆和美术馆作为内容覆盖展示。
2. **内容准入**：先做公开白名单，不在两天内强行批准全部 150 张卡片。
3. **分数表达**：保留辅助分数，但不宣称达到教师精度；重点展示问题、证据和修改建议。
4. **知识图谱**：先做现有链接的轻量可视化，不引入重型图数据库。
5. **部署路线**：正式前端使用 `app.archcritic.cn`，正式 API 使用 `api.archcritic.cn`，两者必须先完成 HTTPS 再录制最终视频。

## 七、冻结验收清单

只有以下项目同时成立，才把参赛版标记为“可提交”：

- [ ] 正式 HTTPS 前端和 API 可访问。
- [ ] 正式账号可以完成知识学习、案例浏览、助手问答、测试、上传、评图和历史查看。
- [ ] 至少一个学习单元完成测试、错题回卡和解锁。
- [ ] 三个典型评图问题可回到正确知识卡和案例。
- [ ] 公开演示内容已经人工确认，来源和图片权利清楚。
- [ ] 助手使用真实模型，无依据时不虚构来源。
- [ ] AI 分数和建议明确标注为教学辅助，不替代教师成绩。
- [ ] 数据、上传文件、知识库和部署配置有可恢复备份。
- [ ] 真实用户试用和三个典型问题验证有原始记录。
- [ ] 3 分钟视频、PPT、技术报告、效果验证报告和复现说明齐全。
- [ ] 在线 Demo 失败时有离线视频和截图备份。
- [ ] 所有材料中的功能、数据和结论与冻结版本一致。
