# ArchCritic 规则卡与学习型知识库设计说明

生成日期：2026-05-26  
适用范围：ArchCritic 多 Agent 评图系统、专项知识库、报告解释界面  
文档定位：系统架构与知识库设计讨论稿  

## 1. 核心结论

ArchCritic 的知识库不应只是“参考资料库”，而应逐步升级为“后台评图规则库 + 前台学习知识库”的组合。

其中：

- 后台规则库服务 Agent，用于问题判定、优势识别、分项扣分和置信度控制。
- 前台学习库服务用户，用于解释本次问题、给出修改建议、展示规范原则、优秀案例和教师说明。

这两类知识不应完全混在一起展示。Agent 需要完整规则，用户只需要看到与本次问题相关的学习解释。

## 2. 类似“错题集”，但不只是错题集

可以把规则卡理解为建筑评图中的“专业错题集”，但它比普通错题集更结构化。

一张规则卡需要回答：

- 这个问题是什么。
- 图纸上通常会表现成什么样。
- 满足哪些证据才可以判定。
- 哪些情况不能误判。
- 属于必须修改、建议优化还是可选深化。
- 会影响哪个专项 Agent、哪个评分项。
- 大致扣分范围是什么。
- 应该如何修改。
- 可以关联哪些规范、案例或教师经验。

但知识库不应只收录问题，也应收录优势。建筑评图不仅是纠错，还要识别设计潜力。

因此建议把知识库拆成四类卡：

| 卡片类型 | 使用对象 | 主要作用 |
|---|---|---|
| 问题规则卡 | 后台 Agent | 判断常见问题是否触发，决定问题等级和扣分范围 |
| 优势规则卡 | 后台 Agent | 判断方案是否达到高分条件，识别可保留的设计亮点 |
| 学习解释卡 | 前台用户 | 用简洁语言解释本次问题或优势，告诉用户为什么、怎么改 |
| 案例/规范/教师说明卡 | 前台用户与后台 Agent | 提供专业依据、优秀案例和教学经验 |

## 3. 为什么不能把后台规则卡完整展示给用户

用户点击知识卡片时，不需要看到完整的扣分规则。

原因是：

- 一个问题可能有多种触发情况，用户本次只触发了其中一种。
- 完整规则卡包含扣分范围、误判条件、后台字段，对学生来说信息过多。
- 用户真正需要的是“我这张图哪里出问题、为什么错、下一步怎么改、可以参考什么”。

因此更合理的设计是：

后台使用完整规则卡：

```text
问题定义
触发条件
不能误判的情况
影响评分项
扣分范围
证据等级
must_fix / should_improve / optional 判定
```

前台展示学习解释卡：

```text
你这次的问题是什么
图纸中具体表现在哪里
为什么这是建筑学问题
下一步修改建议
相关案例、规范或教师提示
```

例如后台规则卡可能包含“后勤流线穿越公共区”的八种触发情况，但用户只触发了其中一种：服务入口到后勤空间的路径穿过主门厅。前台就只展示这一种问题，不展示全部后台规则。

## 4. 规则卡与 Agent 评分卡的关系

Agent 评分卡和知识库规则卡有相似处，但职责不同。

### 4.1 Agent 评分卡

Agent 评分卡是总尺度，回答：

- 这个 Agent 评什么。
- 每个分项多少分。
- 什么是高分、中分、低分。
- 缺少图纸时如何处理。
- 证据不足时如何处理。

例如：

```text
入口与到达，满分 25 分。
22-25 分：主入口识别强，到达序列清楚，人行、车行、后勤入口有合理分离和过渡。
18-21 分：主入口基本明确，局部到达路径或前场空间组织偏弱。
```

### 4.2 知识库规则卡

知识库规则卡是具体事件的判定依据，回答：

- 什么叫主入口不清。
- 什么叫后勤流线穿越公共区。
- 什么情况下不能误判。
- 触发后通常影响哪个评分项。
- 扣分建议是多少。
- 用户应该如何修改。

例如：

```text
如果主入口与后勤入口混用，且后勤路径穿越主要公共门厅，则触发“后勤流线穿越公共区”。
影响项：功能与流线 / 流线分析，场地与回应 / 入口与到达。
扣分建议：流线分析扣 3-8 分，入口与到达扣 4-10 分。
```

### 4.3 前台学习卡

前台学习卡是用户解释层，回答：

```text
你这次的问题是后勤路径穿过主要公共空间，容易造成运营干扰。
建议把服务入口、卸货或管理动线调整到相对独立的一侧，避免穿越主要人流空间。
```

三者关系可以概括为：

```text
评分卡决定评分尺度。
规则卡决定具体问题或优势是否触发。
学习卡帮助用户理解本次反馈并完成修改。
```

## 5. Agent 调用规则卡的推荐流程

建议后续系统采用以下流程：

```text
上传图纸与设计说明
↓
图纸事实识别
↓
按 Agent 检索候选规则卡
↓
Agent 判断问题规则 / 优势规则是否触发
↓
根据评分卡给出分项分数
↓
综合评审生成最终报告
↓
前端展示专项评分、问题说明和关联学习卡
```

### 5.1 第一步：图纸事实识别

Agent 先从图纸和说明中提取可确认事实，例如：

- 主入口位于南侧。
- 后勤入口在东侧。
- 报告厅靠近主门厅。
- 有一处大跨度多功能厅。
- 总图中停车区靠近主入口。
- 未见明确结构柱网。

这一步的重点是事实，不是评价。

### 5.2 第二步：候选规则召回

系统或 Agent 根据事实召回可能相关的规则卡。

示例：

| 识别到的事实 | 候选规则卡 |
|---|---|
| 主入口、城市道路、入口广场 | 主入口识别不清、人车混行、入口前场不足 |
| 后勤入口、服务空间、主门厅 | 后勤流线穿越公共区、后场组织不足 |
| 大跨度多功能厅、无柱大厅 | 大空间缺少结构支撑线索、结构意向表达不足 |
| 庭院、广场、绿地 | 室外空间变成剩余空间、室内外联系不足 |

### 5.3 第三步：规则触发判断

召回规则卡不等于直接扣分。Agent 必须继续判断：

- 是否真的满足触发条件。
- 证据是否足够清晰。
- 是否存在不能判定的情况。
- 应归入 must_fix、should_improve、optional 还是 uncertain_observations。

如果证据不足，应降低置信度，而不是强行判定。

### 5.4 第四步：分项评分

触发的问题规则和优势规则共同影响分项评分。

推荐做法不是简单“额外加分”，而是在每个分项的满分范围内判断高低档。

例如“入口与到达”满分 25 分：

- 入口清楚、人车分离、前场空间完整，可进入 22-25 分。
- 没有严重错误但入口体验一般，可进入 18-21 分。
- 主入口不清或人车混杂，应进入更低分段。

这样可以避免总分失控，也更接近设计课评分习惯。

## 6. 是否需要优势规则

需要。

如果知识库只有问题规则，系统会变成偏“找错”的工具。建筑教学还需要识别方案中值得保留和继续发展的部分。

优势规则卡可以包括：

- 入口序列清楚。
- 庭院与公共空间结合好。
- 室内外空间过渡自然。
- 结构秩序服务空间体验。
- 几何形式与功能组织一致。
- 公共空间节点有层次。

优势规则不建议做成满分外额外加分，而应作为高分档依据。

例如：

```text
如果公共空间、庭院和主要流线形成连续序列，可作为“空间构图”进入 22-25 分的依据。
```

## 7. 规则卡制作方式

不建议完全人工从零写，也不建议完全交给 AI 自动生成。

推荐方式：

```text
AI 生成初稿
↓
你和组员检查图纸可判读性
↓
老师或高年级助教抽样审核
↓
真实图纸测试后反向修正
```

### 7.1 具体步骤

1. 列出高频问题清单  
   先从功能、流线、场地、形式、结构五类中整理常见问题。

2. AI 生成规则卡初稿  
   每张卡包括问题定义、触发条件、不能误判情况、影响分项、扣分范围和修改建议。

3. 检查 AI 可判读边界  
   删除或降级 AI 无法从图纸可靠判断的内容，例如柱子尺寸、梁高、配筋、精确疏散距离。

4. 专业审核  
   老师不一定需要逐字写卡，但应抽样确认规则口径，尤其是 must_fix 触发条件和扣分范围。

5. 用测试图纸修正  
   如果 Agent 经常误判某类问题，就补充“不能判定的情况”。

### 7.2 第一批建议数量

第一版不需要很大，质量比数量更重要。

建议第一批：

| 类型 | 建议数量 |
|---|---:|
| 问题规则卡 | 50 张左右 |
| 优势规则卡 | 20 张左右 |
| 学习解释卡 | 50 张左右，可与问题规则卡一一对应 |
| 案例卡 | 20-30 张 |
| 教师说明卡 | 20 条左右 |

第一版总量约 100-150 张高质量卡片，已经可以明显区别于直接调用通用大模型。

后续成熟阶段可扩展到 150-250 张规则卡，再按建筑类型、设计阶段和课程任务继续扩充。

## 8. 后台规则卡模板

```markdown
# 后勤流线穿越公共区

卡片类型：问题规则卡
适用阶段：方案阶段
适用 Agent：功能与流线 Agent、场地 Agent
影响评分项：流线分析、入口与到达

## 问题定义

后勤、服务、管理或卸货流线需要穿越主要公共空间，造成公共使用和运营管理之间的干扰。

## 可判定条件

- 图纸中可见服务入口、后勤空间或管理空间。
- 从服务入口到后勤空间的路径明显经过主门厅、主要展厅、阅览区或公共活动空间。
- 设计说明没有提供合理解释或分时管理策略。

## 不应判定的情况

- 只上传局部平面，无法确认完整路径。
- 后勤入口不清晰，但也无法确认其穿越公共区。
- 设计说明明确采用分时使用或独立管理，但图纸暂时表达不足。

## 问题等级

- must_fix：后勤流线明确穿越核心公共空间，影响基本运营。
- should_improve：后勤与公共流线局部交叉，但可通过入口和空间调整优化。
- uncertain_observations：图纸看不清后勤路径，只能提示需要补充表达。

## 扣分建议

- 功能与流线 / 流线分析：扣 3-8 分。
- 场地与回应 / 入口与到达：扣 4-10 分。
- 如果缺少总图或服务入口标注，只降低置信度，不宜重扣。

## 修改建议

- 将后勤入口布置到相对独立的一侧。
- 避免服务路径穿越主门厅、主要公共大厅或核心活动空间。
- 在总图和首层平面中补充主入口、后勤入口和服务路径表达。

## 前台学习卡摘要

你这次的问题是后勤路径与主要公共空间发生干扰。公共建筑通常需要把公众到达和服务管理路径分开，否则会影响使用体验和日常运营。建议重新组织服务入口和后勤空间位置，让服务流线在场地侧后方独立进入。
```

## 9. 前台学习卡模板

```markdown
# 后勤流线穿越公共区

## 你这次的问题

后勤或服务路径与主要公共空间发生重叠，容易影响公共使用和运营管理。

## 为什么这是问题

公共建筑通常需要区分公众流线和服务流线。公众流线应清晰、开放、易识别；后勤流线应相对独立，避免穿越门厅、展厅、阅览区或主要活动空间。

## 下一步怎么改

- 把服务入口调整到场地侧后方或次要道路一侧。
- 让后勤空间靠近服务入口，减少穿越公共空间。
- 在总图和首层平面中明确标注公众入口、后勤入口和主要路径。

## 可以参考

- 相关案例：后场组织清晰的社区中心或展览建筑。
- 教师提示：不要只画出房间，还要画清楚不同人群如何到达和使用建筑。
```

## 10. 页面呈现建议

最终报告页面可以采用三层结构：

### 10.1 总评报告

回答：

- 当前方案总体怎么样。
- 哪些问题必须优先修改。
- 哪些优点值得保留。

### 10.2 专项评分展开

回答：

- 每个 Agent 为什么给这个分。
- 每个分项哪里扣分。
- 本次图纸中有哪些证据。
- 哪些内容因为缺图或模糊而无法确认。

### 10.3 关联学习卡

回答：

- 这个问题为什么成立。
- 学生应该如何修改。
- 可以看什么案例、规范或老师说明。

用户不需要看到完整后台规则卡。后台规则卡只用于 Agent 评分和系统调试。

## 11. 推荐落地优先级

建议按以下顺序推进：

1. 先整理 50 张问题规则卡。
2. 同步生成对应的前台学习卡。
3. 为每个专项补 5 张左右优势规则卡。
4. 把规则卡接入 Agent 检索与提示词。
5. 用基准图纸测试触发准确性。
6. 根据误判情况补充“不能判定的情况”。

最先建议覆盖的问题：

- 主入口识别不清。
- 人车流线混杂。
- 后勤流线穿越公共区。
- 功能分区混杂。
- 动静空间互相干扰。
- 平面只是房间堆砌。
- 室外空间变成剩余空间。
- 场地回应不足。
- 形体造型压迫功能。
- 形式与设计概念脱节。
- 大空间缺少结构支撑线索。
- 结构意向表达不足。
- 只有一层平面却被误判为整栋建筑缺失。

## 12. 最终目标

知识库升级后的目标不是让 Agent “多引用几条资料”，而是让系统形成专业判断闭环：

```text
规则卡帮助 Agent 判断和评分。
评分卡控制分数尺度。
学习卡帮助用户理解和修改。
案例、规范、教师说明增强专业可信度。
基准集验证系统是否真的比通用大模型更稳定。
```

这样 ArchCritic 才能真正体现与通用大模型的差异：它不仅会看图和写评语，还能按照建筑教学规则进行可解释的评图。
